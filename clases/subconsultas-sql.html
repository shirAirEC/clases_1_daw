[9.1]

Introducción a las subconsultas

[9.1] Introducción

Introducción a las subconsultas

El uso de subconsultas es una técnica que permite utilizar el resultado de una tabla SELECT en otra consulta SELECT. Permite solucionar consultas complejas mediante el uso de resultados previos conseguidos a través de otra consulta.

El SELECT que se coloca en el interior de otro SELECT se conoce con el término de SUBSELECT. Ese SUBSELECT se puede colocar dentro de las cláusulas:

WHERE   HAVING   FROM   JOIN

🔍 Ejemplo general 
SELECT columnas
FROM   tabla
WHERE  columna operador (SELECT columna FROM otra_tabla);
🔍

[9.2]

Uso de subconsultas en instrucciones SELECT

[9.2.1] Subconsultas simples

Subconsultas simples (escalares)

Devuelven una única fila. Si además devuelven una única columna, se llaman subconsultas escalares (devuelven un único valor).

📐 SINTAXIS 
SELECT listaExpresiones
FROM   tabla
WHERE  expresión OPERADOR
       (SELECT listaExpresiones
        FROM   tabla);
💡 EJEMPLO 
SELECT nombre_empleado, paga
FROM   empleados
WHERE  paga <
       (SELECT paga
        FROM   empleados
        WHERE  nombre_empleado = 'Martina');

El operador puede ser >, <, >=, <=, !=, = o IN.

Esa consulta muestra el nombre y paga de los empleados cuya paga es menor que la de la empleada Martina. Para que funcione, la subconsulta solo puede devolver un valor (solo puede haber una empleada que se llame Martina).

[9.2.1] Subconsultas simples

Varias subconsultas en la misma consulta

Se pueden usar subconsultas las veces que haga falta:

💡 EJEMPLO — empleados que ganan entre Luis y Martina 
SELECT nombre_empleado, paga
FROM   empleados
WHERE  paga <
       (SELECT paga FROM empleados
        WHERE  nombre_empleado = 'Martina')
  AND  paga >
       (SELECT paga FROM empleados
        WHERE  nombre_empleado = 'Luis');
1
La BD calcula el resultado de cada subconsulta (paga de Martina, paga de Luis).
2
Sustituye cada subconsulta por su valor numérico.
3
Devuelve los empleados cuya paga está entre lo que gana Luis (1870 €) y lo que gana Martina (2500 €).

💡 Las subconsultas siempre se encierran entre paréntesis y se deberían colocar a la derecha del operador relacional (recomendado).

[9.2.1] Subconsultas simples

Reglas importantes

⚠️ Regla 1 — valor único

Una subconsulta que utilice los operadores >, <, >=, ... tiene que devolver un único valor, de otro modo ocurre un error.

⚠️ Regla 2 — mismo tipo y número de columnas

Las subconsultas deben devolver el mismo tipo y número de datos para relacionar la subconsulta con la consulta que la utiliza. No puede ocurrir que la subconsulta tenga dos columnas y ese resultado se compare usando una sola columna en la consulta general.

❌ ERROR — más de una fila con operador simple 
-- Si hay varios empleados en la sección 10, esto FALLA:
SELECT nombre FROM empleados
WHERE paga = (SELECT paga FROM empleados WHERE seccion = 10);
-- ORA-01427: single-row subquery returns more than one row
[9.2.2] Subconsultas de múltiples filas

Subconsultas de múltiples filas

A veces se necesitan consultas del tipo: «mostrar el sueldo y nombre de los empleados cuyo sueldo supera al de cualquier empleado del departamento de ventas». La subconsulta devolverá todos los sueldos del departamento de ventas, por tanto no podremos usar un operador de comparación directamente.

La solución es usar instrucciones especiales entre el operador y la consulta:

InstrucciónSignificado
ANY / SOME Compara con cualquier registro de la subconsulta. La instrucción es válida si hay al menos un registro que hace cierta la comparación. (SOME es sinónimo de ANY).
ALL Compara con todos los registros de la subconsulta. La instrucción resulta cierta si lo es toda comparación con los registros de la subconsulta.
IN No usa comparador. Comprueba si un valor se encuentra en el resultado de la subconsulta.
NOT IN Comprueba si un valor NO se encuentra en el resultado de la subconsulta.
[9.2.2] Subconsultas de múltiples filas

Operador ALL

📐 SINTAXIS 
SELECT listaExpresiones
FROM   tabla
WHERE  expresión OPERADOR ALL
       (SELECT listaExpresiones
        FROM   tabla);
💡 EJEMPLO — empleado que más cobra 
SELECT nombre, sueldo
FROM   empleados
WHERE  sueldo >= ALL
       (SELECT sueldo
        FROM   empleados);

La consulta obtiene el empleado que más cobra: su sueldo es mayor o igual que TODOS los sueldos (incluido el suyo).

💡 Equivalencias útiles: > ALL (...) ≡ > MAX(...) · > ANY (...) ≡ > MIN(...) · = ANY (...) ≡ IN (...) · != ALL (...) ≡ NOT IN (...)

[9.2.2] Subconsultas de múltiples filas

Operador IN

📐 SINTAXIS 
SELECT listaExpresiones
FROM   tabla
WHERE  expresión IN
       (SELECT listaExpresiones
        FROM   tabla);
💡 EJEMPLO — empleados que también son directivos 
SELECT nombre
FROM   empleados
WHERE  dni IN
       (SELECT dni
        FROM   directivos);

Se obtienen los nombres de los empleados cuyos DNI están en la tabla de directivos.

El operador IN comprueba si un valor forma parte del conjunto devuelto por la subconsulta. Es la forma habitual de filtrar por pertenencia a un conjunto dinámico.

[9.2.2] Subconsultas de múltiples filas

IN comparando varias columnas

Si se necesita comparar dos columnas en una consulta IN, se escribe así:

💡 EJEMPLO — IN con pares de columnas (cod1, cod2) 
SELECT nombre
FROM   empleados
WHERE  (cod1, cod2) IN
       (SELECT cod1, cod2
        FROM   directivos);

Se agrupan las columnas de la consulta externa entre paréntesis, y la subconsulta debe devolver exactamente las mismas columnas en el mismo orden. Recuerda la regla: mismo tipo y número de columnas.

💡 Esta técnica es muy útil para relaciones que tienen clave primaria compuesta (dos o más columnas que juntas identifican la fila).

[9.2.3] Consultas correlacionadas

Consultas correlacionadas

En las subconsultas a veces se puede desear utilizar datos procedentes de la consulta principal. Eso es posible usando el alias de la tabla de la consulta principal dentro de la subconsulta.

Supongamos que deseamos obtener, de una base de datos geográfica, el nombre y la población de las localidades que son las más pobladas de su provincia.

💡 EJEMPLO — localidad más poblada de cada provincia 
SELECT l.nombre, l.poblacion
FROM   localidades l
WHERE  l.poblacion =
       (SELECT MAX(l2.poblacion)
        FROM   localidades l2
        WHERE  l2.num_provincia = l.num_provincia);

Dentro de la subconsulta usamos el alias l correspondiente a la tabla de localidades de la consulta principal (por eso se le ha puesto como alias l2 a la tabla localidades en la subconsulta).

⚠️ La subconsulta correlacionada se ejecuta una vez por cada fila de la consulta externa. En tablas grandes puede ser lenta.

[9.2.4] Consultas EXISTS

Operador EXISTS

El operador EXISTS devuelve verdadero si la consulta que le sigue devuelve algún valor. Si no, devuelve falso. Se utiliza normalmente mediante consultas correlacionadas.

💡 EJEMPLO — piezas que están en existencias 
SELECT tipo, modelo, precio_venta
FROM   piezas p
WHERE  EXISTS (
         SELECT tipo, modelo
         FROM   existencias
         WHERE  tipo = p.tipo
           AND  modelo = p.modelo
       );

Esta consulta devuelve las piezas que se encuentran en la tabla de existencias (es equivalente al ejemplo con IN sobre múltiples valores).

[9.2.4] Consultas EXISTS

Operador NOT EXISTS

La consulta contraria al EXISTS es:

💡 EJEMPLO — piezas que NO están en existencias 
SELECT tipo, modelo, precio_venta
FROM   piezas p
WHERE  NOT EXISTS (
         SELECT tipo, modelo
         FROM   existencias
         WHERE  tipo = p.tipo
           AND  modelo = p.modelo
       );

Normalmente, las consultas EXISTS se pueden realizar de alguna otra forma con otros operadores (como IN / NOT IN o JOINs).

💡 NOT EXISTS es la forma más segura de buscar «lo que no está», porque —a diferencia de NOT IN— funciona correctamente cuando la subconsulta puede devolver valores NULL.

[9.3] Subconsultas en DML y DDL

¿De qué va este apartado?

La idea es sencilla: utilizar instrucciones SELECT dentro de las instrucciones DML (INSERT, DELETE, UPDATE) e incluso dentro de otras instrucciones DDL.

[9.3.1] INSERT con SELECT

Relleno de registros desde una consulta

La instrucción INSERT puede rellenar datos copiando el resultado de una consulta. En definitiva, permite copiar datos de una tabla a otra.

📐 SINTAXIS 
INSERT INTO tabla (col1, col2, ...)
SELECT expCompatCol1,
       expCompatCol2, ...
FROM   listaDeTablas
[...otras cláusulas del SELECT...];
💡 EJEMPLO — copiar empleados jubilados 
INSERT INTO empleados_jubilados
       (id_emp, nombre, fecha_jub)
SELECT id_empleado,
       nombre_empleado,
       fecha_baja
FROM   empleados
WHERE  situacion = 'JUBILADO';

⚠️ Las columnas del SELECT se tienen que corresponder (en tipo de datos y posición) con las columnas a rellenar mediante INSERT.

[9.3.2] UPDATE con subconsulta

Subconsulta en el apartado WHERE

La instrucción UPDATE permite modificar filas. Es muy habitual usar WHERE para indicar qué filas se modificarán: ahí se pueden usar subconsultas con las mismas posibilidades que en SELECT.

💡 EJEMPLO — subir 10% al sueldo de la sección Producción 
UPDATE empleados
SET    sueldo = sueldo * 1.10
WHERE  id_seccion =
       (SELECT id_seccion
        FROM   secciones
        WHERE  nom_seccion = 'Producción');

Esta instrucción aumenta un 10% el sueldo de los empleados de la sección llamada Producción. La subconsulta devuelve el id_seccion correspondiente, y el UPDATE actualiza a todos los empleados con ese valor.

💡 Si la subconsulta puede devolver más de una fila, usa IN en vez de =.

[9.3.2] UPDATE con subconsulta

UPDATE con subconsulta correlacionada

Es posible utilizar subconsultas correlacionadas dentro de UPDATE:

💡 EJEMPLO — subir 10% solo a empleados con un único empleo en su historial 
UPDATE empleados e
SET    sueldo = sueldo * 1.10
WHERE  1 = (SELECT COUNT(*)
            FROM   historial h
            WHERE  h.id_empleado = e.id_empleado);

Esta consulta aumenta un 10% el sueldo de los empleados si solo han tenido un empleo en su historial. La subconsulta cuenta los registros de historial para cada empleado de la consulta externa (alias e).

⚠️ Algunas versiones antiguas de MySQL no permitían modificar una tabla y usarla a la vez en la subconsulta. Con MySQL moderno esto ya no suele ser un problema.

[9.3.2] UPDATE con subconsulta

Subconsulta en el apartado SET

También podemos utilizar subconsultas en la cláusula SET de la instrucción UPDATE.

💡 EJEMPLO — copiar puesto del empleado 12 a todos los de la sección 23 
UPDATE empleados
SET    puesto_trabajo = (SELECT puesto_trabajo
                         FROM   empleados
                         WHERE  id_empleado = 12)
WHERE  seccion = 23;

Esta instrucción coloca a todos los empleados de la sección 23 el mismo puesto de trabajo que el que posee el empleado número 12.

⚠️ Este tipo de actualizaciones sólo son válidas si el subselect devuelve un único valor (es decir, si utiliza una subconsulta de tipo escalar), que además debe ser compatible con la columna que se actualiza.

[9.3.3] DELETE con subconsulta

Subconsultas en DELETE

Al igual que INSERT o SELECT, la instrucción DELETE dispone de cláusula WHERE donde podemos utilizar subconsultas.

💡 EJEMPLO — borrar empleados con errores graves 
DELETE FROM empleados
WHERE  id_empleado IN
       (SELECT id_empleado
        FROM   errores_graves);

Se eliminan los empleados cuyo identificador esté dentro de la tabla de errores_graves (subconsulta utilizada con el operador IN).

⚠️ Buena práctica

Antes de ejecutar un DELETE con subconsulta, ejecuta un SELECT equivalente para comprobar qué filas vas a borrar:

✅ COMPROBACIÓN PREVIA 
SELECT * FROM empleados
WHERE  id_empleado IN (SELECT id_empleado FROM errores_graves);

[9.4] Subconsultas en FROM y JOIN

Vistas en línea (inline views)

El resultado de un SELECT es una vista (aunque sea temporal, ya que no se almacena de forma permanente). Y las vistas pueden ser utilizadas dentro de otras vistas, al igual que las tablas.

📐 CONSULTA BASE (VISTA DE 3 COLUMNAS) 
SELECT tipo, modelo,
       SUM(cantidad) suma_cantidad
FROM   existencias
GROUP BY tipo, modelo;
💡 USARLA DENTRO DE OTRO SELECT 
SELECT tipo,
       COUNT(modelo),
       SUM(suma_cantidad)
FROM (
  SELECT tipo, modelo,
         SUM(cantidad) suma_cantidad
  FROM   existencias
  GROUP BY tipo, modelo
)
GROUP BY tipo;

⚠️ Las columnas de la subconsulta deben usar alias obligatorios para que no se repita el nombre de la columna, y especialmente en las columnas con datos calculados (SUM, COUNT, etc.).

[9.4] Subconsultas en FROM y JOIN

Subconsultas en JOIN

La posibilidad de usar subconsultas se extiende a la cláusula JOIN:

💡 EJEMPLO — piezas con el precio de venta más alto 
SELECT tipo, modelo, precio_venta
FROM   piezas P1
JOIN (
  SELECT MAX(precio_venta) max_precio_venta
  FROM   piezas
) P2 ON P1.precio_venta = P2.max_precio_venta;

Esta consulta nos muestra el tipo y modelo de las piezas que tienen el precio de venta más alto. No es la única forma de resolverlo, pero nos permite observar la capacidad de usar subconsultas de forma muy avanzada.

A esta técnica se le llama usar vistas en línea (en inglés, inline views).

[9.4] Subconsultas en FROM y JOIN

Ejemplo: empleados cuyo jefe gana más de 2000 €

Primero se hace una consulta que obtiene el nombre e identificador de los empleados que ganan más de 2000 €. Luego se combina con la tabla de empleados de modo que el jefe del empleado esté en esa lista.

💡 SQL-92 (antiguo, con coma) 
SELECT e.nombre
FROM   empleados e,
       (SELECT nombre, id_empleado
        FROM   empleados
        WHERE  salario > 2000) e2
WHERE  e.id_jefe = e2.id_empleado;
💡 SQL-99 (moderno, con JOIN) 
SELECT e.nombre
FROM   empleados e
JOIN   (SELECT nombre, id_empleado
        FROM   empleados
        WHERE  salario > 2000) e2
  ON   (e.id_jefe = e2.id_empleado);

Ambas producen el mismo resultado. La forma SQL-99 con JOIN es la recomendada por ser más legible y explícita sobre las relaciones entre tablas.

[9.5]

Subconsultas escalares

Las que devuelven un único valor

[9.5] Subconsultas escalares

¿Qué son y dónde se pueden usar?

Las subconsultas escalares son aquellas que devuelven un único resultado: SELECT que devuelve una sola fila y un único valor.

Son muy útiles porque se pueden utilizar en muchas partes del lenguaje SELECT. Concretamente:

  • En cualquier cláusula del SELECT (excepto GROUP BY y CONNECT BY)
  • En las funciones CASE y DECODE
  • En cualquier cláusula WHERE de una instrucción DML
  • En la cláusula SET de la instrucción UPDATE

⚠️ Desgraciadamente (y la tentación es grande), no se pueden utilizar en las restricciones CHECK para validar datos. Esta necesidad sólo la pueden resolver los triggers mediante el lenguaje PL/SQL.

[9.5] Subconsultas escalares

Ejemplo: número de provincias por comunidad

💡 EJEMPLO — subconsulta escalar en la lista SELECT 
SELECT nombre,
       (SELECT COUNT(*)
        FROM   comunidades
        JOIN   provincias USING (id_comunidad)
        WHERE  id_comunidad = c.id_comunidad
        GROUP BY id_comunidad
       ) AS numero_provincias
FROM   comunidades c;

Esta consulta obtiene el nombre de cada comunidad autónoma seguida del número de provincias que tiene. Habría otras formas más sencillas de conseguirla (por ejemplo con un JOIN y GROUP BY), pero ilustra cómo una subconsulta escalar produce una columna calculada por fila.

[9.5] Subconsultas escalares

Subconsulta escalar dentro de DECODE

Con imaginación, podemos conseguir consultas tan espectaculares como ésta:

💡 EJEMPLO — comunidad uniprovincial o multiprovincial 
SELECT nombre,
       DECODE(
         (SELECT COUNT(*)
          FROM   comunidades
          JOIN   provincias USING (id_comunidad)
          WHERE  id_comunidad = c.id_comunidad
          GROUP BY id_comunidad),
         1, 'Uniprovincial', 'Multiprovincial'
       )
FROM   comunidades c;

Basada en la anterior: ahora obtenemos el nombre de cada comunidad y un texto que dice si es uniprovincial o multiprovincial. La subconsulta escalar proporciona el valor numérico que DECODE traduce a texto.

💡 En MySQL el equivalente a DECODE es una expresión CASE WHEN ... THEN ... ELSE ... END.

[9.6] CREATE TABLE AS SELECT

Crear tablas a partir de una consulta

La instrucción CREATE TABLE tiene la capacidad de ser utilizada mediante una subconsulta. Se crea una tabla que contiene una copia de los datos de la consulta y cuya estructura se basa en dichos datos.

📐 SINTAXIS 
CREATE TABLE nombreTabla AS
  SELECT ...contenidoConsulta...;
💡 EJEMPLO — tabla resumen de almacenes 
CREATE TABLE resumenAlmacenes AS
  SELECT tipo || '-' || modelo AS clave,
         precio_venta,
         SUM(cantidad) AS cantidad
  FROM   almacen.piezas p
  JOIN   almacen.existencias e
         USING (tipo, modelo)
  GROUP BY tipo, modelo, precio_venta;

⚠️ Estas tablas valen solo como copia de los datos, ya que no contendrán las restricciones habituales (PRIMARY KEY, FOREIGN KEY, etc.) de las tablas relacionales.

💡 En MySQL la sintaxis es exactamente la misma: CREATE TABLE nombre AS SELECT ...;

Ejercicios Prácticos

MySQL Workbench · Base de datos Videoclub

⚙️Preparación del entorno

1
Abre MySQL Workbench y conéctate al servidor local.
2
Ejecuta el script de creación de la base de datos videoclub (versión adaptada a MySQL).
3
Selecciona la base de datos: USE videoclub;
4
Verifica con SHOW TABLES; que tienes: categoria, pelicula, actor, pelicula_actor, cliente, alquiler.

Esquema resumido:

pelicula(pelicula_id, titulo, año_lanzamiento, duracion, clasificacion, precio_alquiler, categoria_id)
alquiler(alquiler_id, pelicula_id, cliente_id, fecha_alquiler, fecha_devolucion, precio_pagado)
cliente(cliente_id, nombre, apellido, email, activo)
actor · pelicula_actor · categoria

🏋️Ejercicio 1 — Subconsultas en SELECT

📝 Enunciados

  1. Muestra los títulos y precios de las películas cuyo precio sea inferior al precio de la película "Matrix".
  2. Lista las películas cuyo precio sea igual o superior al precio máximo de todas las películas de Animación (categoria_id = 7). Usa ALL.
  3. Obtén los nombres de los actores que han actuado en alguna película, usando el operador IN.

✅ Soluciones

1 — películas más baratas que Matrix 
SELECT titulo, precio_alquiler
FROM   pelicula
WHERE  precio_alquiler <
       (SELECT precio_alquiler
        FROM   pelicula
        WHERE  titulo = 'Matrix');
2 — precio >= ALL de Animación 
SELECT titulo, precio_alquiler
FROM   pelicula
WHERE  precio_alquiler >= ALL
       (SELECT precio_alquiler
        FROM   pelicula
        WHERE  categoria_id = 7);
3 — actores con alguna película (IN) 
SELECT nombre, apellido
FROM   actor
WHERE  actor_id IN
       (SELECT actor_id FROM pelicula_actor);

🏋️Ejercicio 2 — Correlacionadas y EXISTS

📝 Enunciados

  1. Usando una subconsulta correlacionada, muestra las películas cuyo precio supere el precio medio de su propia categoría.
  2. Usa EXISTS para listar los clientes que tienen alquileres sin devolver (fecha_devolucion IS NULL).
  3. Usa NOT EXISTS para listar las películas que nunca han sido alquiladas.

✅ Soluciones

1 — precio mayor que la media de su categoría 
SELECT p1.titulo, p1.precio_alquiler, p1.categoria_id
FROM   pelicula p1
WHERE  p1.precio_alquiler >
       (SELECT AVG(p2.precio_alquiler)
        FROM   pelicula p2
        WHERE  p2.categoria_id = p1.categoria_id);
2 — clientes con alquileres pendientes (EXISTS) 
SELECT c.nombre, c.apellido
FROM   cliente c
WHERE  EXISTS (SELECT 1 FROM alquiler a
               WHERE  a.cliente_id = c.cliente_id
                 AND  a.fecha_devolucion IS NULL);
3 — películas nunca alquiladas (NOT EXISTS) 
SELECT p.titulo
FROM   pelicula p
WHERE  NOT EXISTS (SELECT 1 FROM alquiler a
                   WHERE a.pelicula_id = p.pelicula_id);

🏋️Ejercicio 3 — INSERT y UPDATE con subconsulta

📝 Enunciados

  1. Crea la tabla cliente_inactivo(cliente_id, nombre, apellido, email) y copia en ella todos los clientes cuyo campo activo = false usando INSERT ... SELECT.
  2. Sube un 10 % el precio de alquiler a todas las películas cuya categoría sea "Ciencia Ficción" (usando subconsulta en WHERE para obtener el categoria_id).
  3. Actualiza el campo email del cliente id = 1 con el email del cliente cuyo nombre sea "Pedro" (subconsulta escalar en SET).

✅ Soluciones

1 — INSERT ... SELECT 
CREATE TABLE cliente_inactivo (
  cliente_id INT PRIMARY KEY,
  nombre     VARCHAR(100),
  apellido   VARCHAR(100),
  email      VARCHAR(150)
);

INSERT INTO cliente_inactivo (cliente_id, nombre, apellido, email)
SELECT cliente_id, nombre, apellido, email
FROM   cliente
WHERE  activo = false;
2 — UPDATE con subconsulta en WHERE 
UPDATE pelicula
SET    precio_alquiler = precio_alquiler * 1.10
WHERE  categoria_id =
       (SELECT categoria_id FROM categoria
        WHERE  nombre = 'Ciencia Ficción');
3 — UPDATE con subconsulta en SET 
UPDATE cliente
SET    email = (SELECT email FROM cliente
                WHERE nombre = 'Pedro' LIMIT 1)
WHERE  cliente_id = 1;

🏋️Ejercicio 4 — DELETE, FROM y JOIN con subconsulta

📝 Enunciados

  1. Borra con DELETE los alquileres de películas que ya no están en la tabla pelicula (subconsulta con NOT IN). Antes haz un SELECT de comprobación.
  2. Usando una vista en línea en FROM, obtén las 3 categorías con más ingresos totales.
  3. Usando una vista en línea en JOIN, muestra las películas cuyo precio sea el máximo de toda la tabla.

✅ Soluciones

1 — Comprobación + DELETE con NOT IN 
-- 1. Comprobar:
SELECT * FROM alquiler
WHERE  pelicula_id NOT IN (SELECT pelicula_id FROM pelicula);

-- 2. Borrar:
DELETE FROM alquiler
WHERE  pelicula_id NOT IN (SELECT pelicula_id FROM pelicula);
2 — Top 3 categorías por ingresos (vista en línea en FROM) 
SELECT c.nombre, ing.total
FROM   categoria c
JOIN (
  SELECT p.categoria_id,
         SUM(a.precio_pagado) AS total
  FROM   pelicula p
  JOIN   alquiler a USING (pelicula_id)
  GROUP BY p.categoria_id
) ing ON c.categoria_id = ing.categoria_id
ORDER BY ing.total DESC
LIMIT 3;
3 — Películas al precio máximo (JOIN con vista en línea) 
SELECT p.titulo, p.precio_alquiler
FROM   pelicula p
JOIN (
  SELECT MAX(precio_alquiler) AS max_precio
  FROM   pelicula
) m ON p.precio_alquiler = m.max_precio;

🔥Ejercicio 5 — Escalares y CREATE TABLE AS

📝 Enunciados

  1. Muestra cada película junto con una columna calculada usando una subconsulta escalar en el SELECT: nombre, precio y número total de veces que ha sido alquilada.
  2. Con CASE y una subconsulta escalar, marca cada película como «CARA» si su precio supera la media o «NORMAL» en caso contrario.
  3. Crea una tabla resumen_ingresos con CREATE TABLE AS SELECT que contenga, por categoría: número de películas, total de alquileres e ingresos totales.

✅ Soluciones

1 — subconsulta escalar por fila 
SELECT p.titulo,
       p.precio_alquiler,
       (SELECT COUNT(*) FROM alquiler a
        WHERE a.pelicula_id = p.pelicula_id) AS veces_alquilada
FROM   pelicula p
ORDER BY veces_alquilada DESC;
2 — CASE con subconsulta escalar 
SELECT titulo,
       precio_alquiler,
       CASE
         WHEN precio_alquiler > (SELECT AVG(precio_alquiler) FROM pelicula)
              THEN 'CARA'
         ELSE 'NORMAL'
       END AS nivel_precio
FROM   pelicula;
3 — CREATE TABLE AS SELECT 
CREATE TABLE resumen_ingresos AS
  SELECT c.nombre                AS categoria,
         COUNT(DISTINCT p.pelicula_id) AS num_peliculas,
         COUNT(a.alquiler_id)    AS total_alquileres,
         IFNULL(SUM(a.precio_pagado), 0) AS ingresos_totales
  FROM   categoria c
  LEFT JOIN pelicula p ON c.categoria_id = p.categoria_id
  LEFT JOIN alquiler a ON p.pelicula_id  = a.pelicula_id
  GROUP BY c.nombre;
