🔍¿Qué es una Subconsulta?

Definición

Una subconsulta (o subquery) es una consulta SELECT que se escribe dentro de otra consulta SQL.

También se llama subselect, consulta anidada o consulta interna.

¿Por qué son útiles?

  • 🔄 Reutilizar el resultado de una consulta dentro de otra
  • 📊 Filtrar datos basándose en cálculos dinámicos
  • 🎯 Resolver preguntas complejas en un solo paso
  • 🧩 Construir lógica de varias capas sin tablas temporales

💡 Ejemplo del mundo real: "Mostrar las películas cuyo precio sea superior al precio medio de todas las películas" → el "precio medio" hay que calcularlo primero, y luego usarlo como filtro.

🔬Anatomía de una Subconsulta

SELECT titulo, precio_alquiler CONSULTA EXTERNA
FROM pelicula
WHERE precio_alquiler > (
SELECT AVG(precio_alquiler) SUBCONSULTA
FROM pelicula
);

Reglas fundamentales:

1
Paréntesis obligatorios: la subconsulta siempre va entre ( )
2
Se ejecuta primero: MySQL evalúa la subconsulta antes que la consulta externa
3
No termina en ;: el punto y coma solo va al final de toda la sentencia
4
Puede anidarse: una subconsulta puede contener otra subconsulta a su vez

📍¿Dónde se pueden usar?

Las subconsultas pueden aparecer en múltiples cláusulas SQL:

🔍

WHERE

Filtrar filas según el resultado de la subconsulta

📋

FROM

Usar la subconsulta como si fuera una tabla

📊

HAVING

Filtrar grupos basándose en la subconsulta

🗂️

SELECT

Calcular un valor por cada fila del resultado

También en: INSERT, UPDATE y DELETE — pero hoy nos centramos en SELECT.

🗂️Tipos de Subconsultas

Según qué devuelven:

1️⃣

Escalar

Devuelve 1 fila y 1 columna (un único valor)

1 valor
📋

Bloque 1

Subconsultas Escalares en WHERE

Devuelven un único valor para comparar

Bloque 1 · Subconsultas Escalares

🎯Subconsulta Escalar

Devuelve exactamente un valor (una fila, una columna). Se usa con operadores de comparación: =, >, <, >=, <=, !=

Estructura general

SELECT columnas
FROM tabla
WHERE columna OPERADOR (
    SELECT función_agregada(columna)
    FROM tabla
);

⚠️ Si la subconsulta devuelve más de un valor con un operador de comparación simple (=, >...), MySQL dará un error. Usa IN, ANY o ALL para múltiples filas.

Bloque 1 · Subconsultas Escalares

💰Ejemplo: Superior al Promedio

¿Qué películas tienen un precio de alquiler superior al precio medio?

Con subconsulta

SELECT titulo, precio_alquiler
FROM pelicula
WHERE precio_alquiler > (
    SELECT AVG(precio_alquiler)
    FROM pelicula
)
ORDER BY precio_alquiler DESC;
1
MySQL ejecuta primero SELECT AVG(precio_alquiler) FROM pelicula → obtiene, por ejemplo, 3.99
2
Sustituye la subconsulta por ese valor: WHERE precio_alquiler > 3.99
3
Devuelve solo las películas que superen ese umbral

✅ La ventaja: si los precios cambian, la consulta se adapta sola sin tener que cambiar el valor a mano.

Bloque 1 · Subconsultas Escalares

🏆Ejemplo: La Película Más Cara

¿Qué película tiene el precio de alquiler más alto?

Usando MAX() en subconsulta

SELECT titulo, precio_alquiler
FROM pelicula
WHERE precio_alquiler = (
    SELECT MAX(precio_alquiler)
    FROM pelicula
);

💡 ¿Por qué no usar ORDER BY + LIMIT 1?
Porque LIMIT 1 devuelve una película aunque varias tengan el mismo precio máximo. La subconsulta con MAX() devuelve todas las películas que tengan ese precio.

Diferencia entre ambas opciones

-- ❌ Puede perderse empates:
SELECT titulo FROM pelicula ORDER BY precio_alquiler DESC LIMIT 1;

-- ✅ Captura todos los empates:
SELECT titulo FROM pelicula
WHERE precio_alquiler = (SELECT MAX(precio_alquiler) FROM pelicula);
Bloque 1 · Subconsultas Escalares

📈Ejemplo: La Más Alquilada

¿Qué película ha sido alquilada más veces?

Dos subconsultas anidadas

SELECT titulo
FROM pelicula
WHERE pelicula_id = (
    SELECT pelicula_id
    FROM alquiler
    GROUP BY pelicula_id
    ORDER BY COUNT(*) DESC
    LIMIT 1
);

La subconsulta devuelve el pelicula_id con más registros en alquiler. Luego la consulta externa busca el título correspondiente.

Alternativa con subconsulta en FROM: Lo veremos más adelante en el Bloque 4. Cada problema puede tener varias soluciones.

Bloque 1 · Subconsultas Escalares

🔄Subconsulta sobre la Misma Tabla

La subconsulta puede usar la misma tabla que la consulta externa

Películas más cortas que la duración media

SELECT titulo, duracion
FROM pelicula
WHERE duracion < (
    SELECT AVG(duracion)
    FROM pelicula
)
ORDER BY duracion ASC;

Películas anteriores a la más antigua de acción (categoria_id=1)

SELECT titulo, año_lanzamiento
FROM pelicula
WHERE año_lanzamiento < (
    SELECT MIN(año_lanzamiento)
    FROM pelicula
    WHERE categoria_id = 1
);

💡 MySQL en versiones antiguas no permite modificar la misma tabla con UPDATE/DELETE usando subconsulta directa, pero en SELECT no hay restricción.

Bloque 2

Operadores IN y NOT IN

Subconsultas que devuelven múltiples filas

Bloque 2 · IN / NOT IN

📋Operador IN

IN comprueba si un valor está dentro del conjunto de valores devueltos por la subconsulta.

Estructura

SELECT columnas
FROM tabla
WHERE columna IN (
    SELECT columna
    FROM otra_tabla
    WHERE condición
);

¿Qué clientes han alquilado alguna película?

Ejemplo

SELECT nombre, apellido, email
FROM cliente
WHERE cliente_id IN (
    SELECT DISTINCT cliente_id
    FROM alquiler
);

💡 DISTINCT en la subconsulta no es obligatorio cuando se usa IN, pero puede mejorar el rendimiento al reducir duplicados que el motor debe procesar.

Bloque 2 · IN / NOT IN

🎬IN: Ejemplos Prácticos

Películas de categorías con más de 3 películas

SELECT titulo, categoria_id
FROM pelicula
WHERE categoria_id IN (
    SELECT categoria_id
    FROM pelicula
    GROUP BY categoria_id
    HAVING COUNT(*) > 3
);

Actores que han actuado en películas de Ciencia Ficción (categoria_id=5)

SELECT nombre, apellido
FROM actor
WHERE actor_id IN (
    SELECT pa.actor_id
    FROM pelicula_actor pa
    JOIN pelicula p ON pa.pelicula_id = p.pelicula_id
    WHERE p.categoria_id = 5
);

Nota: la subconsulta en IN puede usar JOIN internamente. No hay restricción sobre lo que puede contener la subconsulta.

Bloque 2 · IN / NOT IN

🚫Operador NOT IN

NOT IN devuelve las filas cuyo valor NO aparece en el conjunto de la subconsulta.

Clientes que NUNCA han alquilado

SELECT nombre, apellido, email
FROM cliente
WHERE cliente_id NOT IN (
    SELECT DISTINCT cliente_id
    FROM alquiler
);

Películas que nunca han sido alquiladas

SELECT titulo
FROM pelicula
WHERE pelicula_id NOT IN (
    SELECT DISTINCT pelicula_id
    FROM alquiler
);
Bloque 2 · IN / NOT IN

⚠️El Peligro de NULL con NOT IN

⚠️ Trampa habitual

Si la subconsulta devuelve algún valor NULL, NOT IN no devuelve ninguna fila.

Ejemplo del problema

-- Si alquiler tuviera algún cliente_id NULL:
SELECT nombre FROM cliente
WHERE cliente_id NOT IN (
    SELECT cliente_id FROM alquiler  -- ← puede devolver NULLs
);
-- Resultado: ¡0 filas! Aunque haya clientes sin alquileres

Solución: filtrar NULLs en la subconsulta

SELECT nombre FROM cliente
WHERE cliente_id NOT IN (
    SELECT cliente_id
    FROM alquiler
    WHERE cliente_id IS NOT NULL  -- ← protección contra NULL
);

✅ Como alternativa más segura, usa NOT EXISTS (lo veremos en el Bloque 7): funciona correctamente con NULLs.

⚖️

Bloque 3

Operadores ANY y ALL

Comparar contra un conjunto de valores

Bloque 3 · ANY / ALL

⚖️Operador ANY (= SOME)

ANY compara un valor con cada uno de los valores del conjunto. La condición es verdadera si se cumple con al menos uno.

Estructura

WHERE columna OPERADOR ANY (subconsulta)

Ejemplo: películas más caras que ALGUNA película de animación

-- categoria_id = 7 es Animación
SELECT titulo, precio_alquiler
FROM pelicula
WHERE precio_alquiler > ANY (
    SELECT precio_alquiler
    FROM pelicula
    WHERE categoria_id = 7
)
AND categoria_id != 7;

💡 Equivalencia: > ANY (subconsulta) es equivalente a > MIN(subconsulta) cuando la subconsulta es escalable. = ANY es equivalente a IN.

Bloque 3 · ANY / ALL

🔒Operador ALL

ALL compara un valor con todos los valores del conjunto. La condición es verdadera solo si se cumple con todos y cada uno.

Estructura

WHERE columna OPERADOR ALL (subconsulta)

Ejemplo: películas más caras que TODAS las de animación

-- Devuelve películas cuyo precio supera el precio más alto de Animación
SELECT titulo, precio_alquiler
FROM pelicula
WHERE precio_alquiler > ALL (
    SELECT precio_alquiler
    FROM pelicula
    WHERE categoria_id = 7
);

💡 Equivalencia: > ALL (subconsulta) es lo mismo que > MAX(subconsulta). != ALL es equivalente a NOT IN.

Bloque 3 · ANY / ALL

🆚ANY vs ALL: Resumen

Operador Condición verdadera cuando... Equivalencia
> ANY el valor es mayor que alguno del conjunto > MIN(...)
> ALL el valor es mayor que todos los del conjunto > MAX(...)
= ANY el valor es igual a alguno del conjunto IN (...)
!= ALL el valor es distinto a todos los del conjunto NOT IN (...)
< ANY el valor es menor que alguno del conjunto < MAX(...)
< ALL el valor es menor que todos los del conjunto < MIN(...)

💡 Consejo: Usa MIN() / MAX() cuando la subconsulta es una tabla entera, y ANY / ALL cuando ya tienes la subconsulta escrita con WHERE. El resultado es idéntico.

Bloque 4

Subconsultas en FROM

Tablas derivadas — la subconsulta como tabla

Bloque 4 · Subconsultas en FROM

📊Tablas Derivadas

Cuando una subconsulta aparece en la cláusula FROM, su resultado actúa como una tabla temporal. Se llama tabla derivada.

Debe tener siempre un alias (nombre temporal).

Estructura

SELECT columnas
FROM (
    SELECT ...
    FROM tabla
    WHERE ...
) AS alias_tabla
WHERE condición;

⚠️ El alias AS alias_tabla es obligatorio en MySQL. Sin él, obtendrás un error de sintaxis.

Bloque 4 · Subconsultas en FROM

🗃️Ejemplo: Categorías por Encima del Promedio

¿Qué categorías tienen un precio medio superior al precio medio global?

Con tabla derivada

SELECT resumen.categoria_id, resumen.precio_medio
FROM (
    SELECT categoria_id,
           AVG(precio_alquiler) AS precio_medio,
           COUNT(*)             AS num_peliculas
    FROM pelicula
    GROUP BY categoria_id
) AS resumen
WHERE resumen.precio_medio > (
    SELECT AVG(precio_alquiler)
    FROM pelicula
)
ORDER BY resumen.precio_medio DESC;

La tabla derivada resumen calcula el precio medio por categoría. Luego la consulta externa filtra por encima del promedio global.

Útil para: aplicar WHERE sobre el resultado de un GROUP BY, algo que no puedes hacer directamente en HAVING cuando necesitas mezclar niveles de agregación.

Bloque 4 · Subconsultas en FROM

🔗Tabla Derivada con JOIN

Las tablas derivadas se pueden combinar con JOINs como cualquier tabla.

Ingresos totales por categoría (con nombre)

SELECT c.nombre AS categoria,
       estadisticas.total_alquileres,
       estadisticas.ingresos_totales
FROM categoria c
JOIN (
    SELECT p.categoria_id,
           COUNT(a.alquiler_id)     AS total_alquileres,
           SUM(a.precio_pagado)     AS ingresos_totales
    FROM pelicula p
    JOIN alquiler a ON p.pelicula_id = a.pelicula_id
    GROUP BY p.categoria_id
) AS estadisticas ON c.categoria_id = estadisticas.categoria_id
ORDER BY estadisticas.ingresos_totales DESC;

✅ Este patrón es muy potente: calcula métricas agregadas en la subconsulta y luego enriquece el resultado con datos de otras tablas mediante JOIN.

Bloque 5

Subconsultas en HAVING

Filtrar grupos usando subconsultas

Bloque 5 · Subconsultas en HAVING

📦Subconsultas en HAVING

HAVING filtra grupos (como WHERE filtra filas). Una subconsulta en HAVING permite comparar una función de agregación del grupo con un valor calculado dinámicamente.

Categorías con más películas que la media de películas por categoría

SELECT categoria_id, COUNT(*) AS num_peliculas
FROM pelicula
GROUP BY categoria_id
HAVING COUNT(*) > (
    SELECT AVG(conteo)
    FROM (
        SELECT COUNT(*) AS conteo
        FROM pelicula
        GROUP BY categoria_id
    ) AS subcuentas
);

💡 Nota: Para calcular el promedio de un COUNT necesitamos una tabla derivada (subconsulta dentro de subconsulta), ya que no se puede hacer AVG(COUNT(*)) directamente.

Bloque 5 · Subconsultas en HAVING

💵HAVING: Ingresos sobre Umbral

Clientes cuyos ingresos totales superen el gasto medio de todos los clientes:

SELECT c.nombre,
       c.apellido,
       SUM(a.precio_pagado) AS gasto_total
FROM cliente c
JOIN alquiler a ON c.cliente_id = a.cliente_id
GROUP BY c.cliente_id, c.nombre, c.apellido
HAVING SUM(a.precio_pagado) > (
    SELECT AVG(gasto_por_cliente)
    FROM (
        SELECT SUM(precio_pagado) AS gasto_por_cliente
        FROM alquiler
        GROUP BY cliente_id
    ) AS gastos
)
ORDER BY gasto_total DESC;

✅ Resultado: solo los clientes cuyo gasto total esté por encima del gasto promedio entre todos los clientes.

Bloque 6

Subconsultas Correlacionadas

La subconsulta depende de la consulta externa

Bloque 6 · Subconsultas Correlacionadas

🔗¿Qué es una Subconsulta Correlacionada?

Una subconsulta correlacionada hace referencia a columnas de la consulta externa. No puede ejecutarse de forma independiente.

🔓

No correlacionada

Independiente. Se ejecuta una vez, el resultado se reutiliza para todas las filas.

🔗

Correlacionada

Depende de la fila actual. Se ejecuta una vez por cada fila de la consulta externa.

⚠️ Las subconsultas correlacionadas pueden ser lentas en tablas grandes porque se ejecutan N veces (una por fila). Cuando sea posible, prefiere un JOIN.

Bloque 6 · Subconsultas Correlacionadas

⚙️Cómo se Ejecuta (Paso a Paso)

¿Películas cuyo precio supera el precio medio de su propia categoría?

Subconsulta correlacionada con alias de tabla

SELECT p1.titulo,
       p1.precio_alquiler,
       p1.categoria_id
FROM pelicula p1
WHERE p1.precio_alquiler > (
    SELECT AVG(p2.precio_alquiler)
    FROM pelicula p2
    WHERE p2.categoria_id = p1.categoria_id  -- ← correlación
);
1
La consulta externa toma la primera fila de pelicula (p1), por ejemplo: Matrix con categoria_id=5
2
Ejecuta la subconsulta con ese categoria_id=5: calcula el precio medio de Ciencia Ficción
3
Compara el precio de Matrix con ese promedio. Si supera → se incluye en el resultado
4
Repite para la siguiente fila de p1, y así sucesivamente
Bloque 6 · Subconsultas Correlacionadas

🗂️Correlacionada en la Cláusula SELECT

Una subconsulta correlacionada en el SELECT calcula un valor por cada fila del resultado.

Mostrar cuántas veces ha sido alquilada cada película

SELECT p.titulo,
       p.precio_alquiler,
       (
           SELECT COUNT(*)
           FROM alquiler a
           WHERE a.pelicula_id = p.pelicula_id
       ) AS num_alquileres
FROM pelicula p
ORDER BY num_alquileres DESC;

💡 Alternativa equivalente con JOIN:

SELECT p.titulo, p.precio_alquiler, COUNT(a.alquiler_id) AS num_alquileres
FROM pelicula p
LEFT JOIN alquiler a ON p.pelicula_id = a.pelicula_id
GROUP BY p.pelicula_id, p.titulo, p.precio_alquiler
ORDER BY num_alquileres DESC;
✅

Bloque 7

EXISTS y NOT EXISTS

¿Existe al menos una fila que cumpla la condición?

Bloque 7 · EXISTS / NOT EXISTS

✅Operador EXISTS

EXISTS devuelve TRUE si la subconsulta devuelve al menos una fila. De lo contrario, devuelve FALSE.

Es siempre una subconsulta correlacionada.

Estructura

SELECT columnas
FROM tabla_externa te
WHERE EXISTS (
    SELECT 1   -- el valor seleccionado no importa, solo si hay filas
    FROM tabla_interna ti
    WHERE ti.columna = te.columna  -- correlación
);

Convención: se suele escribir SELECT 1 o SELECT * dentro de EXISTS porque el valor real no importa — solo importa si hay o no filas.

Bloque 7 · EXISTS / NOT EXISTS

🎬EXISTS: Ejemplos

Clientes que han realizado al menos un alquiler

SELECT c.nombre, c.apellido
FROM cliente c
WHERE EXISTS (
    SELECT 1
    FROM alquiler a
    WHERE a.cliente_id = c.cliente_id
);

Películas alquiladas por clientes de más de 2 alquileres totales

SELECT DISTINCT p.titulo
FROM pelicula p
WHERE EXISTS (
    SELECT 1
    FROM alquiler a
    JOIN cliente c ON a.cliente_id = c.cliente_id
    WHERE a.pelicula_id = p.pelicula_id
      AND (
          SELECT COUNT(*) FROM alquiler a2
          WHERE a2.cliente_id = c.cliente_id
      ) > 2
);
Bloque 7 · EXISTS / NOT EXISTS

🚫NOT EXISTS

NOT EXISTS devuelve TRUE si la subconsulta no devuelve ninguna fila. Es la forma más segura de buscar "lo que no está".

Clientes que NUNCA han alquilado (comparativa)

-- Con NOT IN (peligro con NULLs):
SELECT nombre FROM cliente
WHERE cliente_id NOT IN (SELECT DISTINCT cliente_id FROM alquiler);

-- Con NOT EXISTS (seguro con NULLs):
SELECT c.nombre, c.apellido
FROM cliente c
WHERE NOT EXISTS (
    SELECT 1
    FROM alquiler a
    WHERE a.cliente_id = c.cliente_id
);

✅ NOT EXISTS maneja correctamente los valores NULL porque no compara valores — solo comprueba si hay filas.

Bloque 7 · EXISTS / NOT EXISTS

🆚EXISTS vs IN: ¿Cuál Elegir?

CriterioINEXISTS
Si la subconsulta devuelve pocas filas ✅ Eficiente Similar
Si la subconsulta devuelve muchas filas ⚠️ Puede ser lento ✅ Más eficiente
Posibles valores NULL en la subconsulta ⚠️ Problema con NOT IN ✅ Seguro
Subconsulta correlacionada No aplica ✅ Diseñado para esto
Legibilidad para "¿existe al menos uno?" Posible con IN ✅ Más expresivo

💡 Regla práctica: usa EXISTS cuando quieres verificar la existencia de datos relacionados. Usa IN cuando tienes una lista concreta de valores o una subconsulta pequeña.

Bloque 8

Subconsultas Anidadas

Una subconsulta dentro de otra subconsulta

Bloque 8 · Subconsultas Anidadas

🪆Subconsultas Anidadas

Una subconsulta puede contener otra subconsulta en su interior. MySQL permite múltiples niveles de anidamiento (hasta 32 niveles).

Clientes que han alquilado películas de la categoría más cara

SELECT DISTINCT c.nombre, c.apellido
FROM cliente c
WHERE c.cliente_id IN (
    SELECT a.cliente_id
    FROM alquiler a
    WHERE a.pelicula_id IN (
        SELECT p.pelicula_id
        FROM pelicula p
        WHERE p.categoria_id = (
            SELECT categoria_id
            FROM pelicula
            GROUP BY categoria_id
            ORDER BY AVG(precio_alquiler) DESC
            LIMIT 1
        )
    )
);

💡 Lectura de adentro hacia afuera: 1) ¿Cuál es la categoría con precio medio más alto? 2) ¿Qué películas pertenecen a esa categoría? 3) ¿Quién las ha alquilado?

Bloque 8 · Subconsultas Anidadas

📐Legibilidad con Indentación

La clave para entender subconsultas complejas es indentarlas bien:

Mismo ejemplo con indentación clara

-- Nivel 0: consulta principal
SELECT DISTINCT c.nombre, c.apellido
FROM cliente c
WHERE c.cliente_id IN (

    -- Nivel 1: clientes que alquilaron esas películas
    SELECT a.cliente_id
    FROM alquiler a
    WHERE a.pelicula_id IN (

        -- Nivel 2: películas de la categoría más cara (en media)
        SELECT p.pelicula_id
        FROM pelicula p
        WHERE p.categoria_id = (

            -- Nivel 3: categoría con precio medio más alto
            SELECT categoria_id
            FROM pelicula
            GROUP BY categoria_id
            ORDER BY AVG(precio_alquiler) DESC
            LIMIT 1
        )
    )
);

⚠️ Más de 3 niveles suele ser señal de que la consulta se puede reescribir con JOINs o CTEs para mejorar la legibilidad y el rendimiento.

Bloque 9

Subconsultas vs JOINs

¿Cuándo usar cada técnica?

Bloque 9 · Subconsultas vs JOINs

⚖️Subconsultas vs JOINs

Muchas consultas con subconsulta se pueden reescribir con JOIN y viceversa:

Con subconsulta

SELECT nombre, apellido
FROM cliente
WHERE cliente_id IN (
    SELECT DISTINCT cliente_id
    FROM alquiler
);

Equivalente con JOIN

SELECT DISTINCT c.nombre, c.apellido
FROM cliente c
JOIN alquiler a ON c.cliente_id = a.cliente_id;

💡 En muchos casos, el optimizador de MySQL convierte internamente el IN en un JOIN. El rendimiento suele ser equivalente, pero el JOIN es más explícito sobre las relaciones.

Bloque 9 · Subconsultas vs JOINs

🗺️Guía de Decisión

SituaciónRecomienda
Filtrar con un valor calculado (promedio, máximo...) ✅ Subconsulta escalar
Buscar filas "que no tienen" equivalente ✅ NOT EXISTS o LEFT JOIN + IS NULL
Combinar datos de múltiples tablas ✅ JOIN
Necesitas columnas de ambas tablas en el resultado ✅ JOIN
Calcular métricas agregadas y luego filtrar ✅ Tabla derivada (subconsulta en FROM)
La subconsulta es compleja y reutilizable ✅ CTE (WITH) — más legible
Comprobar existencia de datos relacionados ✅ EXISTS
Bloque 9 · Subconsultas vs JOINs

📝Introducción a WITH (CTE)

Una CTE (Common Table Expression) es una subconsulta con nombre, declarada antes de la consulta principal con WITH. Más legible que subconsultas anidadas.

Reescribir el ejemplo del Bloque 4 con CTE

-- Sin CTE (subconsulta en FROM):
SELECT resumen.categoria_id, resumen.precio_medio
FROM (
    SELECT categoria_id, AVG(precio_alquiler) AS precio_medio
    FROM pelicula GROUP BY categoria_id
) AS resumen
WHERE resumen.precio_medio > (SELECT AVG(precio_alquiler) FROM pelicula);

-- Con CTE (más legible):
WITH resumen AS (
    SELECT categoria_id, AVG(precio_alquiler) AS precio_medio
    FROM pelicula
    GROUP BY categoria_id
)
SELECT categoria_id, precio_medio
FROM resumen
WHERE precio_medio > (SELECT AVG(precio_alquiler) FROM pelicula);

✅ MySQL soporta CTEs desde la versión 8.0. Las CTEs hacen el código más fácil de leer y mantener.

💎Buenas Prácticas con Subconsultas

✅ Haz esto

  • Indenta la subconsulta con claridad
  • Usa alias descriptivos en tablas derivadas
  • Usa NOT EXISTS en lugar de NOT IN cuando puedan existir NULLs
  • Verifica la subconsulta por separado antes de integrarla
  • Considera reescribir con CTE si hay 3+ niveles
  • Añade LIMIT 1 en subconsultas escalares si sabes que hay un único resultado

❌ Evita esto

  • Subconsultas correlacionadas en tablas de millones de filas
  • NOT IN sin protección contra NULL
  • Subconsultas escalar donde puede haber múltiples filas
  • Anidar más de 3 niveles sin usar CTEs
  • Usar subconsultas cuando un JOIN es más simple y equivalente

💡 Truco de depuración: si una subconsulta da resultados inesperados, ejecútala sola primero, asegúrate de que devuelve lo que esperas, y luego intégrala en la consulta principal.

🏋️Ejercicio 1 — Nivel Básico

📝 Enunciados

  1. Muestra los títulos y precios de alquiler de las películas cuyo precio sea igual o superior al precio máximo de todas las películas de animación (categoria_id = 7).
  2. Lista los clientes (nombre y apellido) que han realizado más alquileres que la media de alquileres por cliente.
  3. Obtén el nombre de los actores que no han actuado en ninguna película de terror (categoria_id = 4).

✅ Soluciones

1 — Películas al precio máximo de animación

SELECT titulo, precio_alquiler FROM pelicula
WHERE precio_alquiler >= (
    SELECT MAX(precio_alquiler) FROM pelicula WHERE categoria_id = 7
);

2 — Clientes con más alquileres que la media

SELECT c.nombre, c.apellido
FROM cliente c
WHERE (
    SELECT COUNT(*) FROM alquiler a WHERE a.cliente_id = c.cliente_id
) > (
    SELECT AVG(total) FROM (
        SELECT COUNT(*) AS total FROM alquiler GROUP BY cliente_id
    ) AS cuentas
);

3 — Actores sin películas de terror

SELECT nombre, apellido FROM actor
WHERE actor_id NOT IN (
    SELECT pa.actor_id
    FROM pelicula_actor pa
    JOIN pelicula p ON pa.pelicula_id = p.pelicula_id
    WHERE p.categoria_id = 4
);

🏋️Ejercicio 2 — Nivel Medio

📝 Enunciados

  1. Muestra las películas cuya duración sea superior a la duración de TODAS las películas de comedia (categoria_id = 2).
  2. Encuentra los clientes que han alquilado alguna película con precio de alquiler superior a 4€. Usa el operador ANY en la subconsulta.
  3. Obtén las categorías (solo el categoria_id) en las que el precio medio de alquiler es superior al precio medio global. Muestra también el precio medio de cada categoría.

✅ Soluciones

1 — Más largas que todas las comedias

SELECT titulo, duracion FROM pelicula
WHERE duracion > ALL (
    SELECT duracion FROM pelicula WHERE categoria_id = 2
)
ORDER BY duracion DESC;

2 — Clientes con ANY precio > 4

SELECT DISTINCT c.nombre, c.apellido
FROM cliente c
JOIN alquiler a ON c.cliente_id = a.cliente_id
WHERE a.precio_pagado > ANY (
    SELECT precio_alquiler FROM pelicula WHERE precio_alquiler > 4
);

3 — Categorías con precio medio superior al global

SELECT categoria_id, ROUND(AVG(precio_alquiler), 2) AS precio_medio
FROM pelicula
GROUP BY categoria_id
HAVING AVG(precio_alquiler) > (
    SELECT AVG(precio_alquiler) FROM pelicula
)
ORDER BY precio_medio DESC;

🏋️Ejercicio 3 — EXISTS y Correlacionadas

📝 Enunciados

  1. Usa EXISTS para listar los clientes que tienen alquileres sin devolver (fecha_devolucion IS NULL).
  2. Usa NOT EXISTS para listar las películas que nunca han sido alquiladas.
  3. Con una subconsulta correlacionada, muestra cada película junto al número de veces que ha sido alquilada y el total de ingresos generados por esa película.

✅ Soluciones

1 — Clientes con alquileres pendientes (EXISTS)

SELECT c.nombre, c.apellido
FROM cliente c
WHERE EXISTS (
    SELECT 1 FROM alquiler a
    WHERE a.cliente_id = c.cliente_id
      AND a.fecha_devolucion IS NULL
);

2 — Películas nunca alquiladas (NOT EXISTS)

SELECT p.titulo
FROM pelicula p
WHERE NOT EXISTS (
    SELECT 1 FROM alquiler a
    WHERE a.pelicula_id = p.pelicula_id
);

3 — Estadísticas por película (correlacionada en SELECT)

SELECT
    p.titulo,
    (SELECT COUNT(*) FROM alquiler a WHERE a.pelicula_id = p.pelicula_id)
        AS num_alquileres,
    (SELECT IFNULL(SUM(precio_pagado), 0) FROM alquiler a
        WHERE a.pelicula_id = p.pelicula_id)
        AS ingresos_totales
FROM pelicula p
ORDER BY num_alquileres DESC;

🏋️Ejercicio 4 — Tablas Derivadas

📝 Enunciados

  1. Usando una subconsulta en FROM, obtén el top 3 de clientes con más ingresos generados para el videoclub (más alquileres × precio). Muestra nombre, apellido y total gastado.
  2. Con una tabla derivada, obtén qué actores son los más populares: los que han actuado en las películas más alquiladas. Muestra nombre, apellido y total de alquileres de sus películas.

✅ Soluciones

1 — Top 3 clientes por gasto

SELECT c.nombre, c.apellido, gasto.total_gastado
FROM cliente c
JOIN (
    SELECT cliente_id, SUM(precio_pagado) AS total_gastado
    FROM alquiler
    GROUP BY cliente_id
) AS gasto ON c.cliente_id = gasto.cliente_id
ORDER BY gasto.total_gastado DESC
LIMIT 3;

2 — Actores más populares por alquileres

SELECT a.nombre, a.apellido,
       SUM(popularidad.alquileres) AS total_alquileres_peliculas
FROM actor a
JOIN pelicula_actor pa ON a.actor_id = pa.actor_id
JOIN (
    SELECT pelicula_id, COUNT(*) AS alquileres
    FROM alquiler
    GROUP BY pelicula_id
) AS popularidad ON pa.pelicula_id = popularidad.pelicula_id
GROUP BY a.actor_id, a.nombre, a.apellido
ORDER BY total_alquileres_peliculas DESC
LIMIT 10;

🔥Ejercicio 5 — Desafío Final

📝 Enunciados avanzados

  1. Obtén la lista de películas cuyo precio de alquiler supera el promedio de su categoría Y que además han sido alquiladas al menos una vez. Muestra título, precio, categoría y número de alquileres.
  2. Encuentra los clientes "leales": los que han alquilado películas de al menos 3 categorías distintas. Muestra nombre, apellido y número de categorías distintas.
  3. Reescribe la consulta del enunciado 1 usando una CTE (WITH) en lugar de subconsultas anidadas.

✅ Soluciones

1 — Películas sobre promedio de su categoría y con alquileres

SELECT p.titulo, p.precio_alquiler, p.categoria_id,
    (SELECT COUNT(*) FROM alquiler a WHERE a.pelicula_id = p.pelicula_id) AS alquileres
FROM pelicula p
WHERE p.precio_alquiler > (
    SELECT AVG(p2.precio_alquiler)
    FROM pelicula p2
    WHERE p2.categoria_id = p.categoria_id
)
AND EXISTS (
    SELECT 1 FROM alquiler a WHERE a.pelicula_id = p.pelicula_id
)
ORDER BY alquileres DESC;

2 — Clientes con 3+ categorías distintas alquiladas

SELECT c.nombre, c.apellido,
    COUNT(DISTINCT p.categoria_id) AS categorias_distintas
FROM cliente c
JOIN alquiler a ON c.cliente_id = a.cliente_id
JOIN pelicula p ON a.pelicula_id = p.pelicula_id
GROUP BY c.cliente_id, c.nombre, c.apellido
HAVING COUNT(DISTINCT p.categoria_id) >= 3
ORDER BY categorias_distintas DESC;

3 — Reescritura con CTE

WITH promedio_categoria AS (
    SELECT categoria_id, AVG(precio_alquiler) AS precio_medio
    FROM pelicula
    GROUP BY categoria_id
),
alquileres_pelicula AS (
    SELECT pelicula_id, COUNT(*) AS num_alquileres
    FROM alquiler
    GROUP BY pelicula_id
)
SELECT p.titulo, p.precio_alquiler, p.categoria_id,
       IFNULL(ap.num_alquileres, 0) AS alquileres
FROM pelicula p
JOIN promedio_categoria pc ON p.categoria_id = pc.categoria_id
LEFT JOIN alquileres_pelicula ap ON p.pelicula_id = ap.pelicula_id
WHERE p.precio_alquiler > pc.precio_medio
  AND ap.num_alquileres IS NOT NULL
ORDER BY ap.num_alquileres DESC;

📖Resumen de la Clase

🎯 Subconsulta escalar
Un valor → operadores =, >...

📋 IN / NOT IN
Lista de valores → filtrar filas

⚖️ ANY / ALL
Comparar contra un conjunto

📊 FROM (tabla derivada)
La subconsulta actúa como tabla

📦 HAVING
Filtrar grupos con valores calculados

🔗 Correlacionadas
Dependen de la consulta externa

✅ EXISTS / NOT EXISTS
Comprobar existencia de datos

🪆 Anidadas + CTE
Varios niveles → WITH para legibilidad

Regla de oro: usa subconsultas cuando el valor que necesitas filtrar depende de los datos. Usa JOINs cuando necesitas combinar columnas de varias tablas.
