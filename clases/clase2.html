📋¿Qué es un DTD?

DTD significa Document Type Definition (Definición de Tipo de Documento).

Es un conjunto de reglas que define:

  • Qué elementos pueden aparecer en el documento
  • En qué orden deben aparecer
  • Cuántas veces pueden repetirse
  • Qué atributos tiene cada elemento
  • Qué valores son válidos
💡 Analogía: Si XML es un lenguaje, DTD es su gramática. Define las reglas sintácticas que debe seguir el documento.
Introducción al concepto de DTD. Enfatiza que DTD es como un contrato: define qué está permitido y qué no. Un XML puede ser bien formado pero no válido según un DTD.

⚖️Bien formado vs Válido

✅ XML Bien Formado

<?xml version="1.0"?>
<libro>
  <titulo>XML Básico</titulo>
  <autor>Juan Pérez</autor>
</libro>

✓ Sintaxis correcta
✓ Etiquetas cerradas
✓ Una raíz

⚠️ ¿Es válido?

Depende del DTD...

Si el DTD dice:
"libro debe tener un precio"
→ Este XML NO es válido

Si el DTD dice:
"libro solo necesita título y autor"
→ Este XML SÍ es válido

Ejemplo visual de la diferencia entre bien formado y válido. Un documento puede estar bien formado pero no ser válido según un DTD. La validez depende de las reglas definidas en el DTD.

📂DTD Interno vs Externo

📄 DTD Interno

El DTD está dentro del mismo archivo XML

<?xml version="1.0"?>
<!DOCTYPE libro [
  <!ELEMENT libro (titulo,autor)>
  <!ELEMENT titulo (#PCDATA)>
  <!ELEMENT autor (#PCDATA)>
]>
<libro>
  <titulo>XML</titulo>
  <autor>Juan</autor>
</libro>

✅ Todo en un archivo
❌ No reutilizable

🔗 DTD Externo

El DTD está en un archivo separado (.dtd)

<?xml version="1.0"?>
<!DOCTYPE libro SYSTEM "libro.dtd">
<libro>
  <titulo>XML</titulo>
  <autor>Juan</autor>
</libro>

Archivo libro.dtd:

<!ELEMENT libro (titulo,autor)>
<!ELEMENT titulo (#PCDATA)>
<!ELEMENT autor (#PCDATA)>

✅ Reutilizable
✅ Más organizado

Diferencia entre DTD interno (dentro del XML) y externo (archivo separado). En producción se usa más el externo porque es reutilizable. SYSTEM indica archivo local, PUBLIC indica DTD público estándar.

🔤Declarar elementos en DTD

Sintaxis general:

<!ELEMENT nombre-elemento contenido>

Tipos de contenido:

Tipo Ejemplo Significado
#PCDATA <!ELEMENT nombre (#PCDATA)> Solo texto
EMPTY <!ELEMENT br EMPTY> Elemento vacío
ANY <!ELEMENT div ANY> Cualquier contenido
Hijos <!ELEMENT libro (titulo,autor)> Elementos hijos específicos
Sintaxis para declarar elementos en DTD. #PCDATA = Parsed Character Data (texto que puede contener entidades). EMPTY para elementos vacíos como br, img, etc. ANY es poco restrictivo, se usa raramente en producción.

🔢Operadores de secuencia y repetición

Operador Significado Ejemplo
, Secuencia (en ese orden) (titulo, autor)
| Alternativa (uno u otro) (email | telefono)
? Opcional (0 o 1 vez) subtitulo?
* Cero o más veces comentario*
+ Una o más veces capitulo+
💡 Ejemplo completo: <!ELEMENT libro (titulo, autor+, capitulo*, precio?)>
Significa: título (obligatorio), uno o más autores, cero o más capítulos, precio opcional.
Operadores para controlar la secuencia y cantidad de elementos. Estos operadores son similares a expresiones regulares. Practica con ejemplos: un libro con título, múltiples autores, capítulos opcionales.

📖Ejemplo completo: Biblioteca

DTD:

<!ELEMENT biblioteca (libro+)>
<!ELEMENT libro (titulo, autor+, editorial, año, precio?)>
<!ELEMENT titulo (#PCDATA)>
<!ELEMENT autor (#PCDATA)>
<!ELEMENT editorial (#PCDATA)>
<!ELEMENT año (#PCDATA)>
<!ELEMENT precio (#PCDATA)>

XML válido:

<?xml version="1.0"?>
<!DOCTYPE biblioteca SYSTEM "biblioteca.dtd">
<biblioteca>
  <libro>
    <titulo>Aprendiendo XML</titulo>
    <autor>María García</autor>
    <autor>Pedro López</autor>
    <editorial>TechBooks</editorial>
    <año>2026</año>
    <precio>29.99</precio>
  </libro>
</biblioteca>
✅ Este XML es válido porque: Tiene al menos un libro, con título, al menos un autor, editorial, año, y opcionalmente precio.
Ejemplo completo de DTD con elementos. Nota el uso de autor+ (uno o más autores). precio? es opcional (algunos libros pueden no tener precio público). Pregunta a los estudiantes: ¿Sería válido sin precio? Sí. ¿Sin autor? No.

🏷️Declarar atributos en DTD

Sintaxis:

<!ATTLIST nombre-elemento
  atributo1 tipo restricción
  atributo2 tipo restricción
>

Tipos de datos:

  • CDATA - Texto sin procesar
  • ID - Identificador único
  • IDREF - Referencia a un ID
  • NMTOKEN - Token sin espacios
  • (valor1|valor2|valor3) - Lista de valores permitidos

Restricciones:

  • #REQUIRED - Obligatorio
  • #IMPLIED - Opcional
  • #FIXED "valor" - Valor fijo
  • "valor-por-defecto" - Valor por defecto si no se especifica
Declaración de atributos con ATTLIST. CDATA es el tipo más común (cualquier texto). ID debe ser único en todo el documento. #REQUIRED vs #IMPLIED: obligatorio vs opcional.

📝Ejemplos de declaración de atributos

<!-- Atributo obligatorio de tipo texto -->
<!ATTLIST libro isbn CDATA #REQUIRED>

<!-- Atributo opcional -->
<!ATTLIST libro edicion CDATA #IMPLIED>

<!-- Atributo con valor por defecto -->
<!ATTLIST libro idioma CDATA "español">

<!-- Atributo con valores enumerados -->
<!ATTLIST libro formato (papel|digital|audio) #REQUIRED>

<!-- Atributo con valor fijo -->
<!ATTLIST libro moneda CDATA #FIXED "EUR">

<!-- ID único -->
<!ATTLIST libro id ID #REQUIRED>
🎯 Uso en XML: <libro isbn="978-84-9999-999-9" formato="digital" id="libro001">
Ejemplos prácticos de declaración de atributos. isbn es obligatorio (todos los libros deben tenerlo). formato usa enumeración (solo puede ser papel, digital o audio). idioma tiene valor por defecto "español" si no se especifica.

🔗Entidades en DTD

Las entidades permiten definir atajos reutilizables en el documento.

Entidad interna:

<!ENTITY empresa "TechBooks Editorial S.L.">
<!ENTITY email "contacto@techbooks.com">

Uso en XML: &empresa; → TechBooks Editorial S.L.

Entidad externa:

<!ENTITY copyright SYSTEM "copyright.txt">

Incluye el contenido de un archivo externo

💡 Ventaja: Si cambias el nombre de la empresa en el DTD, se actualiza en todos los XMLs que lo usen.
Entidades para reutilizar contenido. Similar a variables o constantes en programación. Útil para textos que se repiten: nombres de empresas, avisos legales, etc. Entidades externas permiten incluir archivos (cuidado con seguridad).

🎯Ejemplo DTD completo

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE catalogo [
  <!-- Definición de entidades -->
  <!ENTITY empresa "TechBooks">
  
  <!-- Definición de elementos -->
  <!ELEMENT catalogo (libro+)>
  <!ELEMENT libro (titulo, autor+, precio)>
  <!ELEMENT titulo (#PCDATA)>
  <!ELEMENT autor (#PCDATA)>
  <!ELEMENT precio (#PCDATA)>
  
  <!-- Definición de atributos -->
  <!ATTLIST libro
    isbn CDATA #REQUIRED
    formato (papel|digital|audio) "papel"
    disponible (si|no) #REQUIRED
  >
]>

<catalogo>
  <libro isbn="978-1-2345-6789-0" formato="digital" disponible="si">
    <titulo>Aprende XML con &empresa;</titulo>
    <autor>Ana Martínez</autor>
    <precio>24.99</precio>
  </libro>
</catalogo>
Ejemplo completo de DTD interno con entidades, elementos y atributos. Nota el uso de &empresa; que se expande a "TechBooks". Este es un ejemplo de DTD que podrías usar en producción.

  • El contacto puede tener atributo tipo con valores: "personal", "trabajo", "familia"

Escribe el DTD completo

Incluye declaración de elementos y atributos

🆕Introducción a XML Schema (XSD)

XSD (XML Schema Definition) es la evolución de DTD.
Es el método recomendado actualmente por el W3C para validar XML.

Características principales:

  • ✅ Usa sintaxis XML (más fácil de aprender y procesar)
  • ✅ Soporta tipos de datos específicos (enteros, fechas, booleanos...)
  • ✅ Permite restricciones avanzadas (rangos, patrones, longitudes)
  • ✅ Soporta espacios de nombres
  • ✅ Más potente y expresivo que DTD
Introducción a XSD como evolución de DTD. XSD es más complejo pero mucho más potente. En esta clase solo veremos introducción, la Clase 3 será completa sobre XSD.

⚖️DTD vs XSD: Diferencias clave

Característica DTD XSD
Sintaxis No es XML (sintaxis SGML) ✅ Es XML
Tipos de datos Solo texto (#PCDATA) ✅ Muchos tipos (int, date, boolean...)
Restricciones Limitadas ✅ Avanzadas (min, max, pattern...)
Namespaces No soporta ✅ Soporta completamente
Complejidad ✅ Simple y ligero Más complejo
Uso actual Legacy / documentos simples ✅ Recomendado por W3C
Tabla comparativa entre DTD y XSD. DTD es más simple pero limitado. XSD es el estándar moderno, especialmente para aplicaciones empresariales.

📄Ejemplo básico: DTD vs XSD

DTD:

<!ELEMENT libro (titulo, autor, año)>
<!ELEMENT titulo (#PCDATA)>
<!ELEMENT autor (#PCDATA)>
<!ELEMENT año (#PCDATA)>

<!ATTLIST libro
  isbn CDATA #REQUIRED
>

XSD equivalente:

<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
  
  <xs:element name="libro">
    <xs:complexType>
      <xs:sequence>
        <xs:element name="titulo" type="xs:string"/>
        <xs:element name="autor" type="xs:string"/>
        <xs:element name="año" type="xs:integer"/>
      </xs:sequence>
      <xs:attribute name="isbn" type="xs:string" use="required"/>
    </xs:complexType>
  </xs:element>
  
</xs:schema>
🎯 Ventaja de XSD: Nota que "año" es de tipo xs:integer. XSD validará que sea un número, mientras que DTD aceptaría cualquier texto.
Comparación lado a lado de DTD vs XSD. XSD es más verboso pero más preciso. Nota el tipo xs:integer para año - DTD no puede hacer esto. La próxima clase (Clase 3) profundizaremos en XSD.

🔢Tipos de datos en XSD (preview)

XSD incluye más de 40 tipos de datos predefinidos:

Texto:

  • xs:string - Cadena de texto
  • xs:token - Texto sin espacios extra
  • xs:normalizedString - Normalizado

Numéricos:

  • xs:integer - Entero
  • xs:decimal - Decimal
  • xs:float, xs:double - Reales

Fecha/Hora:

  • xs:date - Fecha (YYYY-MM-DD)
  • xs:time - Hora (HH:MM:SS)
  • xs:dateTime - Fecha y hora

Otros:

  • xs:boolean - true/false
  • xs:anyURI - URL
  • xs:base64Binary - Binario
📚 En la próxima clase: Veremos cómo usar estos tipos y crear tipos personalizados con restricciones.
Vista previa de los tipos de datos de XSD. Esta es solo una introducción, la Clase 3 será completa sobre XSD. Enfatiza que DTD no tiene ninguno de estos tipos (todo es texto).

🤔¿Cuándo usar DTD vs XSD?

📋 Usa DTD cuando:

  • ✅ Necesitas algo simple y rápido
  • ✅ El documento es muy básico
  • ✅ Trabajas con sistemas legacy
  • ✅ No necesitas validación de tipos
  • ✅ El archivo debe ser ligero

Ejemplo: Configuraciones simples, prototipos, documentos internos pequeños.

🎯 Usa XSD cuando:

  • ✅ Necesitas validar tipos de datos
  • ✅ Requieres restricciones avanzadas
  • ✅ Trabajas con namespaces
  • ✅ El proyecto es profesional/empresarial
  • ✅ Necesitas documentación clara

Ejemplo: APIs, intercambio de datos B2B, aplicaciones empresariales, servicios web.

💼 Recomendación: Para proyectos nuevos, usa XSD. Solo usa DTD si tienes razones específicas (simplicidad, compatibilidad).
Guía práctica para decidir entre DTD y XSD. En el mundo real moderno, XSD es el estándar. DTD todavía se usa en sistemas legacy o para prototipos rápidos.
