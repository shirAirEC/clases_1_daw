❓¿Qué es XML y para qué sirve?

XML en una frase:
XML es un formato para almacenar e intercambiar información de forma estructurada.

Se usa cuando necesitamos que distintos programas o sistemas entiendan los datos de forma clara.

Ejemplos de uso:

💾

Almacenamiento de datos

🔄

Intercambio entre aplicaciones

📡

Sindicación de contenidos

🔧

Configuración de software

XML es un metalenguaje que permite definir nuestros propios lenguajes de marcado. Es texto plano, lo que lo hace portable y legible tanto para humanos como para máquinas. Ejemplos reales: feeds RSS, archivos de configuración, intercambio de datos entre APIs, documentos Office.

📜De dónde viene XML (idea general)

  • 📖 SGML es un "lenguaje base" del que derivan otros lenguajes de marcado.
  • 🌐 XML surge como una forma legible y estructurada de representar información.
  • 🏷️ A diferencia de otros lenguajes de marcado, en XML las etiquetas pueden describir el significado de los datos.
💡 Concepto clave: XML es extensible: tú defines las etiquetas según tus necesidades.
SGML (Standard Generalized Markup Language) es muy complejo. HTML es fijo (etiquetas predefinidas como <p>, <div>...). XML es extensible: puedes crear <producto>, <cliente>, <factura>... según tu dominio. Esta flexibilidad hace a XML ideal para intercambio de datos.

🌳Estructura jerárquica (arborescente)

  • 🌲 Un documento XML tiene estructura de árbol.
  • 🌱 Existe un elemento raíz único (el "padre").
  • 🍃 Dentro de la raíz cuelgan elementos hijos (y pueden existir subhijos).

Ejemplo mínimo:

<?xml version="1.0" encoding="utf-8"?>
<padre>
  <hijo>
    <subhijo>...</subhijo>
  </hijo>
</padre>
padre
↓
hijo
↓
subhijo
La estructura jerárquica en árbol es fundamental en XML. Siempre hay UNA y solo UNA raíz. Los elementos se anidan dentro de otros formando una jerarquía padre-hijo. Esta estructura permite organizar la información de forma lógica y navegable.

📄Partes de un documento XML

Un documento XML se divide en dos partes:

1️⃣ Prólogo

Información técnica del documento

<?xml version="1.0" encoding="utf-8"?>

2️⃣ Cuerpo

El elemento raíz y todo lo que contiene

<raiz>
  <elementos>...</elementos>
</raiz>
🔑 Regla clave: La raíz es única y contiene el resto de elementos.
Todo documento XML tiene estas dos partes: prólogo y cuerpo. El prólogo es opcional técnicamente, pero es muy recomendable incluirlo. El cuerpo DEBE tener una única raíz. Si hay dos elementos al mismo nivel en el nivel superior, el XML no es válido. Ejemplo: no puede haber <raiz1> y <raiz2> al mismo nivel sin un padre que los contenga.

⚙️La primera línea: versión y codificación

La primera línea del documento XML indica información técnica:

version

Versión de XML

encoding

Codificación:
UTF-8, ISO-8859-1...

standalone

¿Depende de esquema externo?

Sintaxis de las instrucciones de procesamiento:

Empiezan por <? y terminan por ?>

Ejemplo:

<?xml version="1.0" encoding="utf-8"?>
El prólogo contiene instrucciones de procesamiento. La más importante es la declaración XML con version y encoding. Version: normalmente "1.0" (la más común). Encoding: UTF-8 es el más recomendado (soporta todos los caracteres), ISO-8859-1 para caracteres latinos. Standalone lo veremos en la siguiente slide.

🔍Atributo standalone

standalone="yes"

➡️ El documento no necesita un esquema externo para interpretarse con esas reglas. 

<?xml version="1.0" 
      encoding="utf-8" 
      standalone="yes"?>

standalone="no"

➡️ El documento depende de un esquema externo para completarse/validarse. 

<?xml version="1.0" 
      encoding="utf-8" 
      standalone="no"?>
📝 Nota visual: Hoy solo entendemos el significado. La creación y uso de esquemas se trabaja en clases posteriores.
Standalone indica si el documento es autosuficiente o depende de definiciones externas (DTD/XSD). "yes" = el documento se puede procesar solo. "no" = necesita referencias externas (como un DTD) para entenderse completamente. Por ahora, no se preocupen de esto. Lo veremos en detalle cuando trabajemos con DTD y XSD.

📚Ejemplo completo: catálogo de biblioteca

<?xml version="1.0" encoding="utf-8"?>
<biblioteca>
  <libro>

    <autor>Gabriel García Márquez</autor>

</biblioteca>

Análisis de la estructura:

  • ✅ Prólogo: línea 1
  • ✅ Elemento raíz: <biblioteca>
  • ✅ Hijo directo: <libro>
  • ✅ Subhijos: titulo, autor, año, genero, idioma, paginas, precio

Este es un ejemplo completo de XML bien formado con un dominio diferente (biblioteca en vez de árboles). Esta estructura jerárquica es típica en XML: un contenedor general (biblioteca) que puede tener múltiples libros. Los nombres de los elementos son descriptivos (auto-documentación). 🏷️Marcas o etiquetas (tags)

  • ✏️ En XML podemos definir nuestras propias etiquetas para representar información.
  • 📦 Las etiquetas separan:
    • el contenido (datos),
    • de la estructura (cómo se organizan esos datos).
  • 🔖 Una etiqueta se escribe con los símbolos < y >.
💡 Ventaja de XML: Los nombres de las etiquetas describen el significado de los datos.
Las etiquetas son el elemento básico de XML. A diferencia de HTML (donde las etiquetas están predefinidas), en XML tú decides los nombres. Esto hace que XML sea auto-documentado: solo leyendo las etiquetas entiendes qué tipo de información contienen.

🔖Tipos de etiquetas en XML

Etiqueta de apertura

<casa>

Etiqueta de cierre

</casa>

Etiqueta vacía

<casa/>

❌ Ejemplos de etiquetas NO válidas:

No se permiten espacios dentro del nombre:

<nombre producto> ... </nombre producto>  ❌

No se permite usar / dentro del nombre:

<variedad/precio> ... </variedad/precio>  ❌
Tres tipos de etiquetas: apertura, cierre y vacía (autocierre). Las etiquetas vacías se usan para elementos que no tienen contenido. Reglas: sin espacios en el nombre, sin caracteres especiales como /. Los nombres deben ser descriptivos y seguir las convenciones (veremos las reglas completas en slides siguientes).

📦Elemento = etiqueta + contenido + cierre

Un elemento está compuesto por: 
<nombre>Litchi</nombre>
Apertura:
<nombre>
Contenido:
Litchi
Cierre:
</nombre>
🔑 Regla: El nombre en la etiqueta de cierre debe ser idéntico al de apertura.
Un elemento completo tiene tres partes: apertura, contenido y cierre. El contenido puede ser texto (PCDATA) u otros elementos (jerarquía). XML es case-sensitive: <Nombre> y <nombre> son diferentes. La etiqueta de cierre DEBE tener exactamente el mismo nombre que la de apertura.

⭕Elementos vacíos

Puede existir un elemento sin contenido.

Dos maneras de representarlo:

Forma 1

Apertura y cierre, contenido vacío:

<casado></casado>

Forma 2 (preferida)

Autocierre:

<teléfono n="666777888"/>
💡 Recomendación: Usa la forma 2 (autocierre) para elementos vacíos. Es más concisa.
Los elementos vacíos son válidos en XML. Se usan cuando el elemento solo necesita existir o cuando toda la información está en atributos. La forma con autocierre (<elemento/>) es más limpia y recomendada. Ejemplo práctico: <saltolinea/>, <imagen src="foto.jpg"/>

📏Reglas para que el XML esté bien formado

1️⃣ Anidamiento correcto

Los elementos deben estar anidados correctamente (se cierran en orden inverso a como se abren).

✅ Correcto: 
<a><b></b></a>
❌ Incorrecto: 
<a><b></a></b>

2️⃣ Apertura y cierre

Los elementos no vacíos deben tener apertura y cierre.

✅ Siempre cierra: 
<nombre>Juan</nombre>

3️⃣ Reglas para nombres

  • ❌ No empezar por números
  • ❌ No usar caracteres reservados (< > & ' ")
  • ✅ Pueden empezar por letra, _ o :
  • ❌ No empezar por la palabra "xml" (reservada)
Estas son las reglas fundamentales para XML bien formado. Anidamiento: como las muñecas rusas, se cierran de dentro hacia fuera. XML es estricto: un solo error de sintaxis invalida todo el documento. Nombres: pueden contener letras, números, guiones, guiones bajos y puntos, pero con restricciones en el inicio.

🏷️Atributos

  • 🔖 Un atributo añade una propiedad a un elemento.
  • 📝 Los atributos se escriben dentro de la etiqueta de apertura.
  • ✏️ Formato general: atributo="valor"
  • 🚫 En un mismo elemento no se repite el mismo nombre de atributo.

Ejemplo:

<nombre dni="77777777J">AlumnoLM</nombre>

Análisis:

  • Elemento: <nombre>
  • Atributo: dni
  • Valor del atributo: "77777777J"
  • Contenido del elemento: AlumnoLM
💡 Consejo: Usarlos con criterio: demasiados atributos pueden hacer el XML menos claro.
Los atributos van SIEMPRE en la etiqueta de apertura, nunca en la de cierre. Los valores de los atributos DEBEN ir entre comillas (simples o dobles). No puede haber dos atributos con el mismo nombre en el mismo elemento. Cuándo usar atributos vs elementos: es un debate. Regla general: atributos para metadatos/propiedades simples, elementos para contenido estructurado.

💬Comentarios

  • 📝 Sirven para aclarar el contenido, especialmente en documentos extensos.
  • 📍 Se pueden colocar en casi cualquier parte del documento.
  • 🔍 Los comentarios no se procesan como datos.

Sintaxis:

Comienzan por <!-- y terminan por -->

Ejemplo:

<?xml version="1.0" encoding="utf-8"?>
<agenda>
  <!-- vamos a crear un contacto -->
  <contacto nombre="alumno LM">
    <ciudad>Málaga</ciudad>
  </contacto>
  <!-- Este contacto es de ejemplo -->
</agenda>
Los comentarios son ignorados por el procesador XML. Útiles para: documentar el código, explicar decisiones de diseño, dejar notas para otros desarrolladores. Los comentarios NO pueden anidarse: no puedes tener un comentario dentro de otro comentario. No uses -- dentro del comentario (solo al final para cerrarlo).

📜CDATA: contenido que no se analiza como etiquetas

  • 🔒 CDATA permite escribir contenido que no será procesado como marcado.
  • ⚠️ Es útil cuando el texto incluye símbolos como < y >.
  • 📝 El contenido dentro de CDATA se trata como texto literal.

Sintaxis:

<![CDATA[contenido dentro del bloque]]>

Ejemplo:

<?xml version="1.0"?>
<asignaturas>
  <foro>
    <![CDATA[el <b>examen</b> será el día <u>viernes</u>]]>
  </foro>
</asignaturas>

Sin CDATA, los símbolos <b> y </b> serían interpretados como etiquetas XML.

CDATA = Character Data (datos de caracteres). Se usa cuando necesitas incluir texto que contiene caracteres reservados de XML (< > &). Dentro de CDATA puedes escribir cualquier cosa excepto la secuencia ]]> que cierra el bloque. Casos de uso: incluir código HTML o JavaScript dentro de XML, texto con muchos caracteres especiales.

🔤Referencias a entidades y caracteres

Caracteres especiales en XML:

Carácter Nombre Referencia
< Menor que (less than) &lt;
> Mayor que (greater than) &gt;
& Ampersand &amp;
" Comilla doble (quotation) &quot;
' Comilla simple (apostrophe) &apos;
⚠️ Caracteres problemáticos: < y & DEBEN ser escapados siempre. El > es recomendable escaparlo.
Referencias a entidades para caracteres especiales. El < es problemático porque indica inicio de etiqueta. El & es problemático porque inicia una referencia a entidad. Las comillas se usan en atributos, por eso tienen referencias. Siempre usar < en vez de < en el contenido de texto.

🌐Referencias de caracteres Unicode

XML permite incluir cualquier carácter Unicode usando referencias decimales o hexadecimales.

Sintaxis:

Decimal

&#número;

Ejemplo: &#8364; → €

Hexadecimal

ÓDIGO;

Ejemplo: &#x20AC; → €

Ejemplo completo:

<?xml version="1.0" encoding="UTF-8"?>
<productos>
  <nombre precio="12.56&#8364;">Gorro de lana</nombre>
  <nombre precio="16.99&#x20AC;">Gorro polar</nombre>
</productos>
Referencias de caracteres Unicode permiten incluir cualquier símbolo. Útil para símbolos de monedas, caracteres especiales, emojis, etc. El código decimal se obtiene de la tabla Unicode. El código hexadecimal usa la misma tabla pero en base 16. Ejemplo: Euro (€) = decimal 8364 = hexadecimal 20AC.

🏷️Espacios de nombres (Namespaces)

Los espacios de nombres resuelven conflictos cuando se combinan documentos XML que tienen elementos con el mismo nombre pero significados diferentes.

Problema: Mismo nombre, distinto significado

Carta (naipes)

<carta>
  <palo>Corazones</palo>
  <numero>7</numero>
</carta>

Carta (restaurante)

<carta>
  <plato>Paella</plato>
  <precio>15.50</precio>
</carta>
❓ Problema: Si combinamos ambos XML, ¿cómo distinguimos qué tipo de "carta" es cada una?
Los espacios de nombres (XML Namespaces) resuelven conflictos de nombres. Permiten usar elementos del mismo nombre con significados diferentes en un mismo documento. Se definen usando el atributo xmlns (XML NameSpace). Similar a los paquetes en Java o los namespaces en C++.

🔧Sintaxis de espacios de nombres

Definir un espacio de nombres:

xmlns:prefijo="URI"

Ejemplo resolviendo el conflicto:

<?xml version="1.0" encoding="UTF-8"?>
<documento xmlns:naipes="http://ejemplo.com/naipes"
           xmlns:restaurante="http://ejemplo.com/restaurante">
  
  <naipes:carta>
    <naipes:palo>Corazones</naipes:palo>
    <naipes:numero>7</naipes:numero>
  </naipes:carta>
  
  <restaurante:carta>
    <restaurante:plato>Paella</restaurante:plato>
    <restaurante:precio>15.50</restaurante:precio>
  </restaurante:carta>
  
</documento>
💡 Importante: Los URI no tienen que apuntar a nada real. Su función es ser únicos.
xmlns es el atributo para definir espacios de nombres. El prefijo se añade antes del nombre del elemento con dos puntos. Los URI solo sirven para identificar de forma única, no necesitan existir. Puedes definir los espacios de nombres en el elemento raíz o en elementos internos. Es una buena práctica usar URLs de tu dominio como URI.

⭐Espacio de nombres por defecto

Se puede definir un espacio de nombres por defecto sin usar prefijo.

Sintaxis:

xmlns="URI"

Ejemplo:

<?xml version="1.0" encoding="UTF-8"?>
<documento xmlns="http://ejemplo.com/principal">
  
  <carta>
    <palo>Corazones</palo>
    <numero>7</numero>
  </carta>
  
  <!-- Cambiar espacio de nombres para un elemento -->
  <carta xmlns="http://ejemplo.com/restaurante">
    <plato>Paella</plato>
    <precio>15.50</precio>
  </carta>
  
</documento>
El espacio de nombres por defecto afecta al elemento donde se define y todos sus descendientes. No requiere usar prefijos, haciendo el XML más limpio. Se puede cambiar el espacio de nombres por defecto en elementos internos. Para indicar que un elemento no pertenece a ningún espacio de nombres: xmlns=""

✅XML bien formado vs XML válido

Bien formado (Well-formed)

No tiene errores de sintaxis:

  • ✅ Única raíz
  • ✅ Etiquetas correctamente anidadas
  • ✅ Atributos bien escritos
  • ✅ Referencias a entidades correctas
  • ✅ Comentarios y CDATA válidos

Válido (Valid)

Además de bien formado, cumple con un esquema:

  • ✅ Estructura definida en DTD/XSD
  • ✅ Elementos permitidos correctos
  • ✅ Atributos obligatorios presentes
  • ✅ Tipos de datos correctos
  • ✅ Orden de elementos válido
📌 Regla de oro: Un XML válido siempre está bien formado, pero un XML bien formado puede no ser válido.
Bien formado = cumple las reglas sintácticas de XML. Válido = cumple además un esquema (DTD, XSD, RELAX NG). Hoy nos enfocamos en XML bien formado. La validación con esquemas se verá en clases posteriores. Un documento puede estar bien formado pero no tener ningún sentido semántico.
