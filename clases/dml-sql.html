Introducción

¿Qué es el DML?

Definición

Data Manipulation Language — Lenguaje de Manipulación de Datos. Es el subconjunto de SQL que nos permite gestionar e interactuar con la información que ya está almacenada en las tablas de la base de datos.

INSERT

Agrega un nuevo registro (fila) a una tabla.

DELETE

Borra registros completos (filas) de una tabla.

UPDATE

Actualiza o cambia valores dentro de registros existentes.

💡 El DML no altera la estructura de las tablas (eso es DDL). Solo trabaja con los datos que viven dentro de ellas.
INSERT — Sintaxis 1

INSERT con columnas nombradas

sintaxis explícita 
INSERT INTO nombre_tabla (columna1, columna2, columna_n)
VALUES (valor1, valor2, valor_n);
  • Correspondencia 1 a 1 — cada columna nombrada debe tener su valor correspondiente en la misma posición. 01:06
  • No es necesario incluir todas las columnas — solo las obligatorias (NOT NULL) y las que quieras rellenar. 01:29
  • El orden importa dentro de lo que escribas — pero no tiene que coincidir con el orden de creación de la tabla, siempre que columna y valor estén alineados.
✅ Esta sintaxis es la más segura y recomendada porque queda claro qué valor va en qué columna.
INSERT — Sintaxis 2

INSERT sin nombres de columna

sintaxis simplificada 
INSERT INTO nombre_tabla
VALUES (valor1, valor2, ..., valor_n);
  • Se omiten los nombres de las columnas. 05:07
  • Los valores deben ir en el mismo orden en que se crearon las columnas en la tabla. Puedes verificarlo con DESCRIBE nombre_tabla. 06:18
  • Si una columna no tiene valor, se escribe explícitamente NULL (siempre que la columna lo permita). 05:38
💡 Usa DESCRIBE nombre_tabla para ver el orden exacto de las columnas antes de usar esta sintaxis.
ejemplo con NULL 
INSERT INTO employees
VALUES (210, 'García', 'Luis', 'LGARCIA', NULL, SYSDATE, 'SA_REP', 3500, NULL, 145, 80);
INSERT — Sintaxis 3

INSERT a partir de un SELECT

inserción múltiple 
INSERT INTO nombre_tabla
SELECT columna1, columna2, ...
FROM   otra_tabla
WHERE  condicion;
  • Permite insertar múltiples filas de golpe extrayendo datos de otra tabla.
  • La estructura del SELECT (número de columnas y tipos de datos) debe coincidir perfectamente con la tabla destino. 08:40
  • No se usa la cláusula VALUES — el SELECT la reemplaza.
🔄 Ejemplo real: El profesor extrae representantes de ventas de employees e inserta sus datos directamente en la tabla departments creando 4 filas de una sola vez.
ejemplo del video 
INSERT INTO departments
SELECT employee_id, last_name, manager_id, department_id
FROM   employees
WHERE  job_id = 'SA_REP';  -- inserta 4 filas de golpe
DELETE

Borrar registros de una tabla

sintaxis 
DELETE FROM nombre_tabla
WHERE  condicion;
  • Elimina filas completas de una tabla — no columnas individuales.
  • La palabra FROM es opcional en algunos gestores, pero es buena práctica incluirla siempre. 12:45
  • La cláusula WHERE es indispensable para indicar qué filas se borran. 12:56
⚠️
¡CUIDADO! Si olvidas el WHERE, se borran TODAS las filas de la tabla en una sola ejecución, a menos que la integridad referencial lo bloquee. 13:11
borrado por rango 
DELETE FROM employees
WHERE employee_id > 206;
borrado por lista 
DELETE FROM departments
WHERE department_id
  IN (174, 176, 178, 202);
UPDATE

Actualizar datos existentes

sintaxis 
UPDATE nombre_tabla
SET    columna1 = valor_nuevo1,
       columna2 = valor_nuevo2
WHERE  condicion;
  • La cláusula SET define qué columnas cambian y cuál es su nuevo valor. Se pueden actualizar varias columnas a la vez separando con comas. 18:12
  • La cláusula WHERE selecciona exactamente qué filas se van a modificar. Sin ella, se modifican todas. 18:46
ejemplo del video — update múltiple con condición compuesta 
UPDATE employees
SET    salary        = 2700,
       department_id = 80,
       commission_pct = 0.27,
       manager_id    = 149
WHERE  job_id  = 'ST_CLERK'
  AND  salary  > 3000;  -- afecta a 2 empleados
UPDATE — Nivel avanzado

Transformaciones en el SET

El SET no solo asigna valores fijos — permite expresiones, funciones y subconsultas.

ejemplo complejo del video — empleados contratados en 1ª mitad del año 99 
UPDATE employees
SET    salary     = salary * 1.25,                          -- 🔢 operación matemática
       email      = SUBSTR(first_name,1,1) || SUBSTR(last_name,1,7),  -- 🔡 función de texto
       manager_id = (SELECT manager_id                       -- 🔍 subconsulta
                      FROM   employees
                      WHERE  first_name = 'Pat'
                        AND  last_name  = 'Fay'),
       hire_date  = hire_date + 1                             -- 📅 suma de días
WHERE  EXTRACT(YEAR FROM hire_date)  = 1999
  AND  EXTRACT(MONTH FROM hire_date) <= 6;
🔢 Matemáticas

Aumentar el salario un 25%: salary = salary * 1.25

🔡 Funciones

Generar email concatenando partes del nombre con SUBSTR.

🔍 Subconsulta

Asignar el mismo jefe que tiene otro empleado con un SELECT anidado.

Buenas prácticas

Tips y salvavidas

🎯
El truco del SELECT previo 14:06
Antes de ejecutar un DELETE o un UPDATE, haz primero un SELECT con la misma cláusula WHERE. Así verás exactamente qué registros se van a ver afectados antes de confirmar la operación.
paso 1 — verifica primero 
SELECT * FROM employees
WHERE job_id  = 'ST_CLERK'
  AND salary > 3000;
-- ¿Son los que quiero modificar?
paso 2 — ejecuta con confianza 
UPDATE employees
SET    salary = 2700
WHERE  job_id  = 'ST_CLERK'
  AND  salary > 3000;
🛟
ROLLBACK — el salvavidas 23:06
Si ejecutas un UPDATE o DELETE equivocado, ROLLBACK deshace todos los cambios y devuelve la base de datos al estado anterior — siempre que no hayas ejecutado COMMIT aún.
deshacer cambios 
ROLLBACK;  -- vuelve al último estado confirmado con COMMIT
Ejemplos prácticos

INSERT — Paso a paso

1
Inserción nombrando columnas — "Perico de los Palotes"
Usa SYSDATE para asignar la fecha de hoy automáticamente.
INSERT INTO employees (employee_id, last_name, email, hire_date, job_id) VALUES (207, 'de los Palotes', 'PPALOTES', SYSDATE, 'SA_REP');
2
Conversión de fecha — "Juan sin Miedo"
Inserta una fecha convirtiendo un texto con función de formateo.
INSERT INTO employees (employee_id, last_name, email, hire_date, job_id) VALUES (208, 'sin Miedo', 'JMIEDO', TO_DATE('15/03/2024','DD/MM/YYYY'), 'SA_REP');
3
Columnas en distinto orden — "María Castaña"
El orden de columnas en el INSERT no importa, siempre que los valores coincidan. También incluye horas, minutos y segundos.
4
Sin nombres de columna — "Paca Prendas"
Se deben poner todos los valores en el orden exacto de la tabla. Verifica el orden con DESCRIBE employees.
5
Con valores NULL — "Luz Cuesta"
Sintaxis directa. Si falta un dato, se escribe obligatoriamente la palabra NULL.
INSERT INTO employees VALUES (211, 'Cuesta', 'Luz', 'LCUESTA', NULL, SYSDATE, 'SA_REP', 3200, NULL, 145, 80);
6
Inserción desde SELECT — "Departamentos basura"
Extrae representantes de ventas e inserta sus datos directamente en departments creando 4 filas de golpe.
INSERT INTO departments SELECT employee_id, last_name, manager_id, department_id FROM employees WHERE job_id = 'SA_REP';
Ejemplos prácticos

DELETE — Limpiando la base de datos

El profesor elimina todo lo que insertó en los pasos anteriores usando dos estrategias diferentes.

1
Borrado por rango — empleados ficticios
Como el último empleado real era el 206, se usa una condición de rango para borrar todos los que se añadieron después.
DELETE FROM employees WHERE employee_id > 206; -- borra todos los ficticios de una vez
2
Borrado por lista de IDs — departamentos basura
No se puede usar "mayor que" porque borraría departamentos reales. Se buscan los IDs exactos y se usa IN.
DELETE FROM departments WHERE department_id IN (174, 176, 178, 202);
💡
Elige el filtro correcto para cada caso:
  • Usa rangos (>, <, BETWEEN) cuando los IDs son consecutivos y no hay riesgo de borrar datos reales.
  • Usa listas (IN) cuando necesitas precisión quirúrgica con IDs concretos.
Ejemplos prácticos

UPDATE — De sencillo a complejo

1
Update sencillo — Randall Matos (emp. 143)
Cambia el departamento del empleado 143 del depto. 50 al 70.
UPDATE employees SET department_id = 70 WHERE employee_id = 143;
2
Update múltiple con condición compuesta
Afecta a 2 empleados que son ST_CLERK y cobran más de 3000. Modifica 4 columnas a la vez. El profesor usa ROLLBACK para deshacer el cambio y volver a los datos originales.
UPDATE employees SET salary = 2700, department_id = 80, commission_pct = 0.27, manager_id = 149 WHERE job_id = 'ST_CLERK' AND salary > 3000; ROLLBACK; -- deshace el cambio → vuelven a cobrar 3000
3
Update muy complejo — funciones + subconsulta
Empleados contratados en la 1ª mitad del año 99. Se modifican salario, email, jefe y fecha de contratación de una sola vez.
UPDATE employees SET salary = salary * 1.25, email = SUBSTR(first_name,1,1) || SUBSTR(last_name,1,7), manager_id = (SELECT manager_id FROM employees WHERE first_name='Pat' AND last_name='Fay'), hire_date = hire_date + 1 WHERE EXTRACT(YEAR FROM hire_date) = 1999 AND EXTRACT(MONTH FROM hire_date) <= 6;
