📖¿Qué es el DML?

DML = Data Manipulation Language (Lenguaje de Manipulación de Datos)

Es el subconjunto de SQL que nos permite gestionar e interactuar con los datos que ya están almacenados en las tablas de la base de datos.

🏗️ DDL — Estructura

Define cómo son las tablas

  • CREATE TABLE
  • ALTER TABLE
  • DROP TABLE

🛠️ DML — Datos

Trabaja con lo que hay dentro de las tablas

  • INSERT → Añadir filas
  • DELETE → Borrar filas
  • UPDATE → Modificar filas

INSERT

Agrega una nueva fila a una tabla

DELETE

Elimina filas enteras de una tabla

UPDATE

Cambia valores en filas existentes

➕INSERT — Sintaxis explícita

Se especifican las columnas que quieres rellenar y sus valores correspondientes.

INSERT INTO nombre_tabla (columna1, columna2, columna_n)
VALUES (valor1, valor2, valor_n);
  • 📌 Debe existir correspondencia 1 a 1 entre columnas y valores en la misma posición. 01:06
  • 📌 No es obligatorio incluir todas las columnas — solo las marcadas como NOT NULL y las que quieras rellenar. 01:29
  • 📌 El orden de las columnas puede ser distinto al orden de creación de la tabla, siempre que columna y valor estén alineados.

Ejemplo — inserción nombrando columnas (emp. 207)

INSERT INTO employees (employee_id, last_name, email, hire_date, job_id)
VALUES (207, 'de los Palotes', 'PPALOTES', SYSDATE, 'SA_REP');

✅ Recomendación: Esta es la sintaxis más segura y legible porque queda claro qué valor va en qué columna.

➕INSERT — Sintaxis directa

Se omiten los nombres de las columnas. Los valores se ponen en el mismo orden que se definió la tabla.

INSERT INTO nombre_tabla
VALUES (valor1, valor2, ..., valor_n);
  • 📌 Los valores deben ir en el mismo orden exacto en que se crearon las columnas en la tabla. 06:18
  • 📌 Si una columna no tiene valor, escribe obligatoriamente NULL (siempre que la columna lo permita). 05:38

💡 Usa DESCRIBE nombre_tabla para ver el orden exacto de las columnas antes de usar esta sintaxis. 05:07

Ejemplo — sintaxis directa con NULL explícito

-- Si no tenemos el first_name ni la comisión, escribimos NULL
INSERT INTO employees
VALUES (211, 'Cuesta', 'Luz', 'LCUESTA', NULL, SYSDATE, 'SA_REP', 3200, NULL, 145, 80);

➕INSERT — Desde una consulta SELECT

Inserta múltiples filas de golpe extrayendo datos de otra tabla mediante un SELECT. No se usa la cláusula VALUES.

INSERT INTO nombre_tabla
SELECT columna1, columna2, ...
FROM   otra_tabla
WHERE  condicion;

⚠️ La estructura del SELECT (número de columnas y tipos de datos) debe coincidir exactamente con la tabla destino. 08:40

Ejemplo — inserción masiva desde SELECT

-- Extrae representantes de ventas y los inserta en departments
INSERT INTO departments
SELECT employee_id, last_name, manager_id, department_id
FROM   employees
WHERE  job_id = 'SA_REP';   -- inserta 4 filas a la vez

✅ Con una sola instrucción se insertaron 4 filas — una por cada representante de ventas encontrado.

💻INSERT — Ejemplos prácticos

A continuación se muestran seis casos de inserción progresivos, partiendo del empleado número 207, que cubren todas las variantes de INSERT.

1

Inserción nombrando columnas

Se especifican las columnas que se van a rellenar. Se puede usar SYSDATE para insertar automáticamente la fecha actual.

2

Inserción con conversión de fecha

Cuando la fecha viene como texto, se convierte con la función TO_DATE('15/03/2024', 'DD/MM/YYYY') antes de insertarla.

3

Columnas en distinto orden

El orden de las columnas en el INSERT no tiene que coincidir con el de la tabla, siempre que cada columna tenga su valor emparejado. También se puede incluir la hora exacta en la fecha.

4

Sin nombrar columnas (sintaxis directa)

Se omiten los nombres de columna y se listan todos los valores en el orden exacto de creación de la tabla. Consulta el orden con DESCRIBE employees.

5

Sintaxis directa con valores NULL

Cuando un campo no tiene dato y la columna lo permite, hay que escribir obligatoriamente la palabra NULL en su posición.

6

Inserción masiva desde SELECT

Se extraen filas de otra tabla con un SELECT y se insertan directamente en la tabla destino, todo en una sola instrucción.

🗑️DELETE — Borrar registros

Elimina filas completas de una tabla. No borra columnas individuales, sino registros enteros.

DELETE FROM nombre_tabla
WHERE  condicion;
  • 📌 La palabra FROM es opcional en algunos gestores, pero es buena práctica incluirla siempre. 12:45
  • 📌 La cláusula WHERE es indispensable para indicar qué filas se borran. 12:56

⛔ ¡PELIGRO!

Si olvidas el WHERE, se borran TODAS las filas de la tabla de una sola vez, a menos que la integridad referencial lo bloquee. 13:11

-- ❌ ESTO BORRA TODA LA TABLA
DELETE FROM employees;

💻DELETE — Práctica: limpiar lo que insertamos

Tras practicar con INSERT, es necesario limpiar los datos de prueba. Veremos dos estrategias de borrado según el tipo de condición.

Paso 1 — Borrado por rango

Como el último empleado real era el 206, usamos una condición de rango para eliminar todos los ficticios.

DELETE FROM employees
WHERE  employee_id > 206;

✅ Elimina todos los empleados añadidos de una vez.

Paso 2 — Borrado por lista (IN)

No podemos usar "mayor que" porque borraría departamentos reales. Buscamos los IDs exactos.

DELETE FROM departments
WHERE  department_id
       IN (174, 176, 178, 202);

✅ Precisión quirúrgica: solo los 4 "basura".

💡 Elige el filtro correcto: Usa rangos (>, BETWEEN) cuando los IDs son consecutivos sin riesgo. Usa listas (IN) cuando necesitas precisión con IDs concretos.

✏️UPDATE — Actualizar datos

Modifica y cambia valores específicos en registros que ya existen en nuestra tabla.

UPDATE nombre_tabla
SET    columna1 = valor_nuevo1,
       columna2 = valor_nuevo2
WHERE  condicion;
  • 📌 SET define qué columnas cambian y cuál es su nuevo valor. Se pueden actualizar varias columnas a la vez separando con comas. 18:12
  • 📌 WHERE selecciona exactamente qué filas se modifican. Sin ella, se modifican TODAS. 18:46

⛔ ¡MISMO PELIGRO QUE DELETE!

Si olvidas el WHERE, actualizarás TODAS las filas de la tabla.

-- ❌ ESTO CAMBIA EL DEPARTAMENTO DE TODOS LOS EMPLEADOS
UPDATE employees SET department_id = 80;

💻UPDATE — De sencillo a complejo (I)

1

Update sencillo — Randall Matos (emp. 143)

Cambia el departamento del empleado 143 del depto. 50 al 70. Solo afecta a una columna y una fila.

UPDATE employees
SET    department_id = 70
WHERE  employee_id   = 143;
2

Update múltiple con condición compuesta

Afecta a los empleados que son ST_CLERK y cobran más de 3000. Modifica 4 columnas a la vez en 2 empleados. Después se usa ROLLBACK para deshacer el cambio y comprobar cómo funciona.

UPDATE employees
SET    salary         = 2700,
       department_id  = 80,
       commission_pct = 0.27,
       manager_id     = 149
WHERE  job_id  = 'ST_CLERK'
  AND  salary  > 3000;      -- afecta a 2 empleados

ROLLBACK;  -- deshace el cambio → vuelven a cobrar 3000

🔬UPDATE — Transformaciones avanzadas (II)

SET no solo asigna valores fijos — también admite expresiones matemáticas, funciones de texto y subconsultas.

3

UPDATE complejo — empleados contratados en la 1ª mitad del año 99 26:05

Se modifican salario, email, jefe y fecha de contratación de una sola instrucción.

UPDATE employees
SET    salary     = salary * 1.25,                              -- 🔢 operación matemática
       email      = SUBSTR(first_name,1,1) || SUBSTR(last_name,1,7), -- 🔡 función de texto
       manager_id = (SELECT manager_id                          -- 🔍 subconsulta
                     FROM   employees
                     WHERE  first_name = 'Pat'
                       AND  last_name  = 'Fay'),
       hire_date  = hire_date + 1                               -- 📅 suma de días
WHERE  EXTRACT(YEAR  FROM hire_date) = 1999
  AND  EXTRACT(MONTH FROM hire_date) <= 6;
🔢

Matemáticas

salary * 1.25
Sube el sueldo un 25%

🔡

Funciones

SUBSTR()
Genera email con partes del nombre

🔍

Subconsulta

SELECT anidado
Asigna el mismo jefe que Pat Fay

✨Buenas prácticas

🎯 El truco del SELECT previo 14:06

Antes de ejecutar un DELETE o un UPDATE, haz primero un SELECT con la misma cláusula WHERE. Así ves exactamente qué registros se van a ver afectados antes de confirmar.

Paso 1 — Verifica primero

-- ¿Son los que quiero modificar?
SELECT * FROM employees
WHERE  job_id  = 'ST_CLERK'
  AND  salary  > 3000;

Paso 2 — Ejecuta con confianza

UPDATE employees
SET    salary = 2700
WHERE  job_id  = 'ST_CLERK'
  AND  salary  > 3000;

🛟 ROLLBACK — El salvavidas 23:06

Si ejecutas un UPDATE o DELETE equivocado, ROLLBACK deshace todos los cambios y devuelve la base de datos al estado anterior — siempre que no hayas ejecutado COMMIT aún.

ROLLBACK;   -- vuelve al último estado confirmado con COMMIT
